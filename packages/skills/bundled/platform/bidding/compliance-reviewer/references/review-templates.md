# Review Templates

Use these prompt templates as building blocks for each review step. Adapt wording to the actual materials and project specifics.

Core design pattern for every step:

```text
角色：明确你在这一步扮演谁。
任务：明确这一步只审查什么，不做什么。
输入：明确需要读取哪些文件、表格或审查清单。
输出：明确必须输出哪些表格、结论或修订建议。
约束：明确不得改写正文、不得自行判断不确定项、哪些事项要人工确认。
下一步：说明下一步审查重点或需要编写师修改什么。
```

## 1. 接收审查材料

```text
你是标书合规审查技能。请确认以下审查材料是否齐全，如有缺失请列出并说明对审查的影响。

所需材料：
- 招标文件全文：
- 评分标准：
- 否决条款清单：
- 资格条件清单：
- 响应矩阵：
- 正文草稿：
- 责任范围说明：
- 格式/页数要求：
- 报价文件（Excel/打印版）：
- 产品清单/技术响应表（货物标/集成标）：
- 证书及检测报告（涉及强制认证时）：
- 厂家授权/证明材料（货物标/集成标）：

请输出：
1. 材料完整性检查表（是否提供、适用条件、备注）；
2. 适用性判断（用户负责范围是否涉及报价/产品，项目类型是否纯服务标）；
3. 如有缺失，说明缺失项对审查范围的影响；
4. 建议补充后再审查，还是可以在现有材料下开始审查。

要求：
- 评分标准和否决条款缺失时，建议补齐后再审查；
- 不得在材料不全时开始完整审查；
- 报价文件缺失时，报价审查步骤标记为"未检查"，不影响其他步骤；
- 产品/证书材料缺失时，产品审查步骤标记为"未检查"，不影响其他步骤。
```

## 2. 评分点响应审核

```text
你是一名投标评分审核专家。请逐条检查每个评分点是否在正文中被明确响应。

输入：
- 评分标准矩阵：
- 正文草稿：
- 响应矩阵：

请按表格输出：
| 评分项 | 分值 | 要求摘要 | 正文位置 | 响应证据 | 缺口状态 | 修订动作 |

缺口状态只能使用：已响应、部分响应、未响应、范围外。

要求：
- 不得遗漏任何评分项；
- 响应是否明确，不是隐含带过；
- 响应是否有招标文件或素材依据；
- 高分值项是否得到充分篇幅；
- 对"部分响应"项说明缺什么、建议怎么补；
- 范围外评分项只做关联提醒。
```

## 3. 硬性要求与否决风险审核

```text
你是一名投标废标风险审查专家。请逐条检查否决条款和硬性要求是否被满足或明确标注。

输入：
- 否决条款清单：
- 资格条件清单：
- 正文草稿：
- 公司资质/材料：

请按表格输出：
| 风险项 | 触发要求/风险来源 | 范围 | 风险等级 | 当前状态 | 需要证据 | 交付前动作 |

风险等级只能使用：致命、高、中、低。
当前状态只能使用：已满足、未满足、待确认、范围外。

要求：
- 否决条款必须逐条核对，不得遗漏；
- 不确定的状态标注"待确认"，不自行判断为"已满足"；
- 致命风险未解决时，审查结论必须为"存在高风险，暂不建议交付"；
- 如果用户只负责部分章节，列出依赖项和交接项，不替别人补全。
```

## 4. 报价数据一致性审查

```text
你是投标报价数据审查专家。请依据采购文件规定的报价口径，对报价文件进行逐行复算和跨文件一致性检查。

输入：
- 报价文件（Excel/打印版）：
- 开标一览表/投标函：
- 采购文件报价规则（限价、小数位、税率、计算口径）：
- 产品清单/技术响应表（用于交叉比对）：

请按表格输出：
1. 报价复算检查表（检查项、位置、期望值、实际值、差异、风险等级、处理建议）
   检查项包括：数量×单价=合价、分类小计、明细合计→总价、投标函总价、开标一览表总价、最高限价、大小写金额、税率/税额
2. 跨文件一致性检查表（文件A、文件B、比对字段、是否一致、差异说明、风险等级）
   比对组：报价表 vs 技术响应表（产品名称/数量/单位/型号）、报价表 vs 产品清单（产品名称/型号/制造商）、报价表 vs 投标函（总价/币种/税率）
3. 同型号价差分析表（型号、位置A、位置B、价格A、价格B、差异分析、是否合理、风险等级）— 仅在有同型号不同价格时输出

要求：
- 逐行核验数量×单价=合价，考虑采购文件规定的小数位和四舍五入规则
- 核验明细合计、分类汇总、分项报价、开标一览表、投标函和投标总价是否一致
- 检查是否超过预算、最高限价、单项限价
- 核对数字金额与大写金额、小数位、币种和含税/不含税口径
- 同型号不同价格不得直接判定为错误，先分析单位/配置/环境/施工难度/含安装
- 不得修改报价文件，不判断报价策略
- 计算过程必须可复现，列出公式和代入值
- 超限价直接标注为致命风险
- 无法确认的差异标注"待确认"，不自行下结论
```

## 5. 产品/型号/证书一致性审查

```text
你是投标产品与证书审查专家。请检查产品/型号/证书在多个文件间的一致性和有效性。

输入：
- 产品清单/技术响应表：
- 报价表中的产品行：
- 证书、检测报告、厂家彩页、技术白皮书：
- 厂家授权书/唯一性说明/定制说明：
- 采购文件中的核心产品清单和认证要求：

请按表格输出：
1. 产品一致性对应表（序号、产品名称、品牌、型号、制造商、报价表✓/✗、技术响应表✓/✗、产品清单✓/✗、彩页/证书✓/✗、一致性、风险等级）
2. 重复/近似型号清单（型号A、型号B、出现位置A、出现位置B、差异类型、是否同一产品、风险等级）— 如有
3. 核心产品/强制认证核验表（产品名称、认证类型、证书编号、持有人、制造商、有效期、投标截止日是否有效、覆盖范围、风险等级）
4. 定制/无型号项目清单（序号、项目名称、当前表述、类型、是否需要补充、补充内容、风险等级）— 如有

要求：
- 不判断产品技术性能
- 查不到≠不合格，无法确认的事项标注"需要进一步核实"
- 不得仅凭型号名称相似就认定为同一产品
- 不得仅凭品牌/型号名称就认定产品不合格
- 分体式/套装设备必须检查证书是否覆盖全部关键组成
- 软件配套产品必须明确软件名称、版本、授权数量
- 证书过期为致命风险
- 核心产品型号在报价表和技术响应表中不一致为高风险
- 需要网络核验时优先使用权威渠道（制造商官网、国家认证认可监督管理部门、认证机构、政府采购平台或电子交易平台），并记录查询日期和限制
- 对"定制、无型号、根据现场情况定制"等项目分类判断：服务类可保留表述，货物类/系统类需补充尺寸、材料、配置、版本、接口、授权数量或唯一产品说明
```

## 6. 内容质量审核

```text
你是一名投标文件质量审查专家。请检查正文的表达质量、幻觉风险、过度承诺等问题。

输入：
- 正文草稿：
- 公司素材（用于核实）：

请按表格输出：
| 问题类型 | 具体位置 | 问题描述 | 风险等级 | 修改建议 |

问题类型包括：幻觉/无依据内容、过度承诺、索引式表达、AI味表达、段落过薄、标题过碎、空话套话。

要求：
- 只指出问题和修改建议，不直接改写正文；
- 幻觉和过度承诺是高风险项，必须醒目标注；
- 索引式表达包括"根据招标文件""详见招标文件"等；
- AI味表达包括"闭环管理""动态调整""持续优化"无具体上下文等。
```

## 7. 重复内容与格式审核

```text
你是一名投标文件格式审查专家。请检查重复内容、标题编号、配图必要性和格式规范。

输入：
- 正文草稿：
- 格式/页数要求：

请输出：
1. 重复内容检查表（问题类型、位置、具体内容、处理建议）；
2. 格式检查表（检查项、状态、说明）。

要求：
- 完全重复段落必须标注；
- 近似重复（只改一两个词）必须标注；
- 标题编号是否出现重复显示；
- Word自动编号与手工编号是否冲突；
- 配图是否真正有助于理解；
- 页数不足时建议通过有用内容扩充，不建议加重复表格或碎标题。
```

## 8. 出具审查报告

```text
请汇总所有审查结果，出具最终审查报告。

请按以下结构输出：
1. 总体结论（可交付 / 需修订后交付 / 存在高风险，暂不建议交付）；
2. 评分点响应审核摘要；
3. 废标/重大风险审核摘要；
4. 报价数据一致性审查摘要（复算错误、跨表不一致、限价风险、同型号价差、是否未检查）；
5. 产品/型号/证书一致性审查摘要（产品不一致、重复型号、证书问题、定制项目、是否未检查/不适用）；
6. 内容质量审核摘要；
7. 重复内容与格式审核摘要；
8. 主要问题汇总表；
9. 范围说明（含未检查步骤及原因）；
10. 待补充材料；
11. 人工确认事项；
12. 已完成检查清单（含报价和产品检查项）；
13. 建议下一步操作。

要求：
- 致命风险未解决时，结论必须为"存在高风险，暂不建议交付"；
- 高风险项未解决时，结论不得为"可交付"；
- 报价超限价→致命→暂不建议交付；
- 核心产品证书过期→致命→暂不建议交付；
- 产品型号跨文件不一致→高→不得标记为可交付；
- 审查报告独立于正文，不混入正文内容；
- 只指出问题和修改建议，不直接改写正文；
- 未检查的步骤必须在报告中标明原因。
```

## 9. 整改复查

```text
你是投标合规复查专家。请对比整改前后文件，确认原问题是否闭环，并检查修改是否引发新问题。

输入：
- 上一轮审查报告（问题清单）：
- 整改后文件（版本）：
- 整改说明：

请按表格输出：
1. 闭环检查表（问题编号、原问题摘要、原风险等级、整改说明、复查结果、新增问题、备注）
   复查结果只能使用：闭环、未闭环、部分闭环
2. 新增冲突检查表（检查项、是否受影响、是否产生新冲突、新冲突描述、风险等级）
   检查项包括：总价/税额、型号/参数、目录/页码、交叉引用、签章位置、文件版本、其他

要求：
- 只检查指定问题的闭环情况，不重新扩展全项目审查；
- 必须回到原文核对，不得凭印象判断"改好了"；
- 如发现与原问题直接关联的新风险，记录并说明关联关系；
- 其他无关事项标记"本轮未检查"；
- 复查结论必须明确：全部闭环 / 部分闭环（列出未闭环项）/ 存在新增问题；
- 整改后必须重新检查总价、型号、页码、目录、交叉引用、签章、文件版本和实际上传文件。
```

## Full Review Execution Prompt

```text
使用 $compliance-reviewer，对这份投标文件进行合规审查。

请严格按 8 步推进（Step 9 整改复查为可选），每一步都记录：
1. 这一步做了什么；
2. 发现了什么问题；
3. 建议怎么修改。

要求：
- 先确认材料齐全，判断报价/产品审查适用性，再开始审查；
- 评分点逐条核对，不得遗漏；
- 否决条款逐条核对，不得遗漏；
- 报价逐行复算，跨表一致性比对；
- 产品型号证书一致性核验；
- 致命风险未解决时，不要给出"可交付"结论；
- 只指出问题和修改建议，不直接改写正文；
- 最后出具完整审查报告。
```

## Re-verification Execution Prompt

```text
使用 $compliance-reviewer 的整改复查功能，对整改后的投标文件进行复查。

输入：
- 上一轮审查报告（含问题清单）
- 整改后的文件（版本）
- 整改说明

要求：
- 逐项确认原问题是否闭环，必须回到原文核对；
- 检查修改是否引发新的金额、型号、证书、页码、目录、交叉引用、签章和版本冲突；
- 只检查指定问题的闭环，不重新扩展全项目；
- 复查结论：全部闭环 / 部分闭环 / 存在新增问题。
```
