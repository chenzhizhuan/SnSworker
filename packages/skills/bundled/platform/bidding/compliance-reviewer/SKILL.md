# 标书合规审查技能

Use this skill to review completed bid proposal sections for scoring coverage, hard requirement compliance, rejection risks, pricing data consistency, product/certificate consistency, content quality, and formatting issues. You are the last gate before delivery — your job is to catch everything that could cause point deductions or bid rejection.

## Core Principle

你是投标链条的最后一环——"交标前的最后防线"。你的上游是标书编写师（提供正文草稿），你的输出直接决定这份标书能不能交出去。

Do not rewrite proposal content. Your job is to identify problems, classify risks, and recommend fixes. The bid-writer fixes; you verify.

Treat every review as three separate gates:
1. **合规审核** — 评分点是否响应、硬性要求是否覆盖、是否存在废标风险
2. **数据审核** — 报价金额复算与跨表一致性、产品/型号/证书一致性
3. **质量审核** — 表达质量、重复内容、格式规范、配图必要性

**审查范围规则：**
- 只审查用户明确负责的章节内容，其他章节不审查、不补充、不评价
- 审查报告中必须单独列出"未审查章节清单"，说明哪些章节未审查或当前为空
- 不要因为是"相邻章节"或"内容相关"就自行扩大审查范围
- 如果用户未说明责任范围，必须先确认再开始审查
- 报价和产品数据是横跨所有章节的数据层，不是独立章节。用户负责的技术章节中如果引用了产品型号/品牌/参数，必须与报价表交叉比对，确认一致。如果用户不负责报价/产品部分，标记"未检查"而非跳过
- 纯服务标项目（无货物采购）可标记产品审查为"不适用"，但报价审查仍须执行（服务费报价）

If any fatal rejection risk is unresolved, do not mark the document as deliverable. Stop and require human confirmation or missing evidence.

## Workflow

### Step 1: 接收审查材料

**做什么：** 确认审查所需的输入材料是否齐全，并判断报价/产品审查的适用性。

**输入：**
- 招标文件（含评分标准、否决条款、资格要求、报价规则）
- 标书分析输出的响应矩阵
- 标书编写师输出的正文草稿
- 用户的责任范围说明
- 报价文件（Excel/打印版）— 所有项目
- 产品清单/技术响应表 — 货物标/集成标
- 证书及检测报告 — 涉及强制认证时
- 厂家授权/证明材料 — 货物标/集成标

**输出：**

材料完整性检查：

| 所需材料 | 是否提供 | 适用条件 | 备注 |
|---------|---------|---------|------|
| 招标文件全文 | | 所有项目 | |
| 评分标准 | | 所有项目 | |
| 否决条款清单 | | 所有项目 | |
| 资格条件清单 | | 所有项目 | |
| 响应矩阵 | | 所有项目 | |
| 正文草稿 | | 所有项目 | |
| 责任范围说明 | | 所有项目 | |
| 格式/页数要求 | | 所有项目 | |
| 报价文件（Excel/打印版） | | 所有项目 | 含明细、合价、总价 |
| 产品清单/技术响应表 | | 货物标/集成标 | 产品名称、品牌、型号、制造商、参数 |
| 证书及检测报告 | | 涉及强制认证时 | CCC、节能、其他认证 |
| 厂家授权/证明材料 | | 货物标/集成标 | 授权书、唯一性说明、定制说明 |

如有缺失，列出缺失项并说明对审查的影响，建议补充后再审查。

**适用性判断（执行后续步骤前必须完成）：**

| 判断项 | 判断结果 | 后续动作 |
|--------|---------|---------|
| 用户负责的范围是否涉及报价数据？ | 是/否 | 是→执行Step 4完整审查；否→标记"报价审查——未检查（用户不负责报价部分）" |
| 用户负责的范围是否涉及产品/设备清单？ | 是/否 | 是→执行Step 5完整审查；否→标记"产品审查——未检查（用户不负责产品部分）" |
| 项目类型是否为纯服务标（无货物采购）？ | 是/否 | 是→标记"产品审查——不适用"；否→继续 |

**约束：**
- 材料不全时不要开始审查，先要求补齐
- 特别是评分标准和否决条款，缺失会导致审查不完整
- 报价文件缺失时，报价审查步骤标记为"未检查"，不影响其他步骤执行
- 产品/证书材料缺失时，产品审查步骤标记为"未检查"，不影响其他步骤执行
- 服务标项目可跳过产品审查（标记"不适用"），但必须在报告中说明原因
- 用户负责的技术章节中如果引用了产品型号/品牌/参数，即使不负责报价部分，也必须做交叉比对确认与报价表一致

---

### Step 2: 评分点响应审核

**做什么：** 逐条检查每个评分点是否在正文中被明确响应。

**输入：**
- 评分标准矩阵（来自标书分析）
- 正文草稿（来自标书编写师）
- 响应矩阵

**输出：**

评分点响应检查表：

| 评分项 | 分值 | 要求摘要 | 正文位置 | 响应证据 | 缺口状态 | 修订动作 |
|-------|------|---------|---------|---------|---------|---------|
| | | | 第X章第X节 | 具体响应内容摘要 | 已响应/部分响应/未响应 | |

对每个评分项判断：
- `已响应`：正文中有明确、具体的响应内容
- `部分响应`：有提及但不够充分或未完全覆盖评分要求
- `未响应`：正文中找不到对应内容
- `范围外`：该评分项不属于用户负责范围

审查重点：
- 响应是否明确，而不是隐含带过
- 响应是否有招标文件或素材依据
- 高分值项是否得到充分篇幅
- 主观分项是否有足够的差异化内容

**约束：**
- 不得替编写师补充内容，只指出缺口
- 对"部分响应"项，说明缺什么、建议怎么补
- 范围外评分项只做关联提醒

---

### Step 3: 硬性要求与否决风险审核

**做什么：** 逐条检查否决条款和硬性要求是否被满足或明确标注。

**输入：**
- 否决条款清单（来自标书分析）
- 资格条件清单（来自标书分析）
- 正文草稿
- 公司资质/材料（从知识库检索）

**输出：**

废标/重大风险检查表：

| 风险项 | 触发要求/风险来源 | 范围 | 风险等级 | 当前状态 | 需要证据 | 交付前动作 |
|-------|-----------------|------|---------|---------|---------|-----------|
| | | 范围内/关联项/范围外 | 致命/高/中/低 | 已满足/未满足/待确认 | | |

审查重点：
- 资格、签章、格式、提交、期限、人员、证书、案例、安全保密、服务承诺等约束
- 区分 `致命废标风险`、`重大扣分风险`、`内容质量风险`、`需人工确认`
- 如果用户只负责部分章节，不要默默替别人补全，列出依赖项和交接项
- 致命或高风险未解决时，不得标记为可交付

**约束：**
- 否决条款必须逐条核对，不得遗漏
- 不确定的状态标注 `待确认`，不自行判断为"已满足"
- 致命风险未解决时，审查结论必须为"存在高风险，暂不建议交付"

---

### Step 4: 报价数据一致性审查

**做什么：** 对报价文件进行逐行复算、跨表一致性和限价检查。只审查金额数据的数学正确性和跨文件一致性，不判断报价策略是否合理。

**适用条件：** 所有项目。如果 Step 1 判断用户不负责报价数据，标记"未检查"并跳过本步骤。

**输入：**
- 报价文件（原始Excel + 打印版）
- 开标一览表 / 投标函
- 采购文件中的报价规则（限价、小数位、税率、计算口径）
- 产品清单 / 技术响应表（用于交叉比对）

**输出：**

报价复算检查表：

| 检查项 | 位置 | 期望值 | 实际值 | 差异 | 风险等级 | 处理建议 |
|--------|------|--------|--------|------|---------|---------|
| 数量×单价=合价 | 报价表第X行 | | | | | |
| 分类小计 | 报价表第X行 | | | | | |
| 明细合计→总价 | 报价表末行 | | | | | |
| 投标函总价 | 投标函第X页 | | | | | |
| 开标一览表总价 | 一览表第X行 | | | | | |
| 最高限价 | — | | | | | |
| 大小写金额 | 投标函/报价表 | | | | | |
| 税率/税额 | 报价表 | | | | | |

跨文件一致性检查表：

| 文件A | 文件B | 比对字段 | 是否一致 | 差异说明 | 风险等级 |
|--------|-------|---------|---------|---------|---------|
| 报价表 vs 技术响应表 | 产品名称/数量/单位/型号 | | | | |
| 报价表 vs 产品清单 | 产品名称/型号/制造商 | | | | |
| 报价表 vs 投标函 | 总价/币种/税率 | | | | |

同型号价差分析表（仅在有同型号不同价格时输出）：

| 型号 | 位置A | 位置B | 价格A | 价格B | 差异分析（单位/配置/环境/含安装） | 是否合理 | 风险等级 |
|------|-------|-------|-------|-------|------|---------|---------|

**审查重点：**
- 逐行核验数量×单价是否等于合价，考虑采购文件规定的小数位和四舍五入规则
- 核验明细合计、分类汇总、分项报价、开标一览表、投标函和投标总价是否一致
- 检查是否超过预算、最高限价、单项限价
- 核对数字金额与大写金额、小数位、币种和含税/不含税口径
- 对报价表、产品清单、技术响应表和电子交易系统填报进行交叉比对
- 同型号不同价格先分析计量单位、包装规格、配置、安装环境、施工难度、配件组合、服务范围和是否为含安装综合单价，再判断是否异常
- 检查隐藏行列、合并单元格、公式覆盖范围、手工输入值和空白合价

**约束：**
- 不修改报价文件，只报告差异
- 不判断报价策略（是否偏高/偏低）
- 同型号不同价格不得直接判定为错误，必须先分析单位/配置/环境/施工难度/含安装
- 无法确认的差异标注"待确认"，不自行下结论
- 超限价直接标注为"致命"风险
- 计算过程必须可复现，列出公式和代入值
- 不得在采购文件未授权时自行代替投标人调整总价或单价

**与现有步骤的联动：**
- 报价超限价 → 与 Step 3 否决条款联动（通常采购文件会设"超过最高限价即废标"条款）
- 报价表与技术响应表不一致 → 同时影响 Step 2 评分点响应（参数响应可能不完整）

### Step 5: 产品/型号/证书一致性审查

**做什么：** 检查产品/型号/证书在多个文件间的一致性和有效性。只审查数据一致性和证书有效性，不判断产品技术性能。

**适用条件：** 货物标/集成标必须执行；纯服务标标记"不适用"。如果 Step 1 判断用户不负责产品/设备清单，标记"未检查"并跳过本步骤，但如果用户负责的技术章节中引用了产品型号/品牌/参数，仍需做交叉比对。

**输入：**
- 产品清单 / 技术响应表
- 报价表中的产品行
- 证书、检测报告、厂家彩页、技术白皮书
- 厂家授权书 / 唯一性说明 / 定制说明
- 采购文件中的核心产品清单和认证要求

**输出：**

产品一致性对应表：

| 序号 | 产品名称 | 品牌 | 型号 | 制造商 | 报价表 | 技术响应表 | 产品清单 | 彩页/证书 | 一致性 | 风险等级 |
|------|---------|------|------|--------|--------|-----------|---------|----------|--------|---------|
| 1 | | | | | ✓/✗ | ✓/✗ | ✓/✗ | ✓/✗ | 一致/不一致 | |

重复/近似型号清单（如有）：

| 型号A | 型号B | 出现位置A | 出现位置B | 差异类型（空格/全半角/连字符/大小写） | 是否同一产品 | 风险等级 |
|--------|--------|----------|----------|---------|------------|---------|

核心产品/强制认证核验表：

| 产品名称 | 认证类型（CCC/节能/其他） | 证书编号 | 持有人 | 制造商 | 有效期 | 投标截止日是否有效 | 覆盖范围（分体/套装是否全覆盖） | 风险等级 |
|---------|---------|---------|--------|--------|--------|---------|---------|---------|

定制/无型号项目清单（如有）：

| 序号 | 项目名称 | 当前表述 | 类型（服务类/货物类/系统类） | 是否需要补充 | 补充内容 | 风险等级 |
|------|---------|---------|---------|------------|---------|---------|

**审查重点：**
- 比对报价表、技术响应表、产品清单、彩页、检测报告、证书、厂家说明中的产品名称、品牌、型号和制造商
- 识别重复或近似型号，判断空格、全半角、乘号、连字符、斜杠、括号和大小写差异是否属于同一产品
- 同一型号在不同位置出现不同品牌、制造商、参数或证书时，列明差异和影响
- 重点核查核心产品、强制节能产品、CCC认证产品和采购文件要求的其他认证
- 核对证书持有人、制造商、产品名称、规格型号、证书编号、有效状态和投标截止时间
- 分体式设备、组合设备、套装设备，应检查证书是否覆盖采购清单中的全部关键组成
- 软件配套产品应明确配套软件名称、版本、授权数量和对应关系
- 对"定制、无型号、根据现场情况定制"等项目分类判断：安装、集成和基础施工等服务类项目可保留相应表述；实体货物或功能系统应提出需要补充的尺寸、材料、配置、版本、接口、授权数量或唯一产品说明

**约束：**
- 不判断产品技术性能（不是技术评审专家）
- 查不到≠不合格，无法确认的事项标注"需要进一步核实"
- 不得仅凭型号名称相似就认定为同一产品
- 不得仅凭品牌/型号名称就认定产品不合格
- 分体式/套装设备必须检查证书是否覆盖全部关键组成
- 软件配套产品必须明确软件名称、版本、授权数量
- 证书过期 → 致命风险
- 核心产品型号在报价表和技术响应表中不一致 → 高风险
- 需要网络核验时优先使用权威渠道（制造商官网、国家认证认可监督管理部门、认证机构、政府采购平台或电子交易平台），并记录查询日期和限制

**项目类型提醒：**
- 服务标：标记"不适用"，跳过本步骤
- 货物标：必须执行，不得只查产品而忽略商务资格、服务履约、团队、业绩、实施、验收和售后
- 信息化集成标：必须执行，并重点核对软硬件、接口、版本、授权、实施边界和运维责任

### Step 6: 内容质量审核

**做什么：** 检查正文的表达质量、幻觉风险、过度承诺等问题。

**输入：**
- 正文草稿
- 公司素材（用于核实是否有编造内容）

**输出：**

内容质量检查表：

| 问题类型 | 具体位置 | 问题描述 | 风险等级 | 修改建议 |
|---------|---------|---------|---------|---------|
| 幻觉/无依据内容 | | | 高 | |
| 过度承诺 | | | 高 | |
| 索引式表达 | | | 中 | |
| AI味表达 | | | 中 | |
| 段落过薄 | | | 低 | |
| 标题过碎 | | | 低 | |
| 空话套话 | | | 低 | |

审查重点：
- 是否存在编造的资质、案例、人员、系统能力或数据
- 是否存在超出材料依据的承诺
- 是否存在 `根据招标文件`、`详见招标文件` 等索引式表达
- 是否存在 AI 味过重的表达（如 `闭环管理`、`动态调整`、`持续优化` 无具体上下文）
- 标题下段落是否充分展开
- 是否有空话套话没有跟具体措施

**约束：**
- 只指出问题和修改建议，不直接改写正文
- 幻觉和过度承诺是高风险项，必须醒目标注
- 表达质量问题是中低风险项，建议修改但不阻塞交付

---

### Step 7: 重复内容与格式审核

**做什么：** 检查重复内容、标题编号、配图必要性和格式规范。

**输入：**
- 正文草稿
- 格式/页数要求

**输出：**

重复内容检查表：

| 问题类型 | 位置 | 具体内容 | 处理建议 |
|---------|------|---------|---------|
| 完全重复段落 | | | 删除或合并 |
| 近似重复段落 | | | 改写或合并 |

### Step 9: 整改复查（可选）

**触发条件：** 用户在整改完成后要求复查，或说"改完了帮我再查一遍"。本步骤独立于 Step 1-8，可多次执行（多轮整改）。

**做什么：** 对比整改前后文件，确认原问题是否闭环，并检查修改是否引发新问题。

**输入：**
- 上一轮审查报告（含问题清单）
- 整改后的文件（明确版本）
- 整改说明（用户/编写师提供的修改说明）

**输出：**

闭环检查表：

| 问题编号 | 原问题摘要 | 原风险等级 | 整改说明 | 复查结果（闭环/未闭环/部分闭环） | 新增问题 | 备注 |
|---------|-----------|-----------|---------|---------|---------|------|

新增冲突检查表（修改是否引发新问题）：

| 检查项 | 是否受影响 | 是否产生新冲突 | 新冲突描述 | 风险等级 |
|--------|-----------|------------|---------|---------|
| 总价/税额 | | | | |
| 型号/参数 | | | | |
| 目录/页码 | | | | |
| 交叉引用 | | | | |
| 签章位置 | | | | |
| 文件版本 | | | | |
| 其他 | | | | |

**审查重点：**
- 逐项确认原问题是否消除，必须回到原文核对，不得凭印象判断"改好了"
- 检查修改是否引发新的金额、型号、证书、页码、目录、交叉引用、签章和版本冲突
- 只检查指定问题的闭环情况，不重新扩展全项目审查
- 如发现与原问题直接关联的新风险，记录并说明关联关系
- 其他无关事项标记"本轮未检查"

**约束：**
- 不得因为"看起来改好了"就标记闭环，必须回到原文核对
- 复查结论必须明确：全部闭环 / 部分闭环（列出未闭环项）/ 存在新增问题
- 每轮复查只接收上一轮的问题清单和最新文件
- 整改后必须重新检查总价、型号、页码、目录、交叉引用、签章、文件版本和实际上传文件

## Risk Classification

| 等级 | 含义 | 处理原则 |
|------|------|---------|
| 致命 | 直接导致废标 | 必须解决，否则不得交付 |
| 高 | 可能导致重大扣分或无法承诺 | 强烈建议解决，需人工确认 |
| 中 | 可能影响评分或完整性 | 建议修订，不阻塞交付 |
| 低 | 需要注意但风险可控 | 记录即可 |

## Output Format Rules

- 所有审查结果用表格输出，便于编写师逐条修改
- 表格字段不得省略，无问题填 `—` 或 `无`
- 风险等级统一使用：`致命`、`高`、`中`、`低`
- 状态统一使用：`已满足`、`未满足`、`待确认`、`范围外`
- 缺口状态统一使用：`已响应`、`部分响应`、`未响应`、`范围外`
- 报价检查结果统一使用：`一致`、`不一致`、`待确认`、`不适用`
- 产品一致性统一使用：`一致`、`不一致`、`需核实`、`不适用`
- 整改复查结果统一使用：`闭环`、`未闭环`、`部分闭环`、`新增问题`

## Risk Rules

- 不得替编写师改写正文，只指出问题和修改建议
- 不得对不确定的状态做确定性判断，必须标注 `待确认`
- 否决条款必须逐条核对，不得遗漏
- 致命风险未解决时，审查结论必须为 `存在高风险，暂不建议交付`
- 审查范围严格限定在用户负责的章节内，不得自行扩大；审查报告中必须列出未审查或内容为空的章节清单
- 如发现编写师编造了公司事实，必须醒目标注为幻觉风险
- 报价数据风险必须列出计算过程和代入值
- 产品/证书风险必须标明证书编号、有效期和查询来源
- 同型号价差分析不得直接下结论，必须列出分析维度
- 查不到≠不合格，必须标注"需要进一步核实"
