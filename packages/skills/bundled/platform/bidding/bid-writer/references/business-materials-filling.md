# 商务材料自动填充流程（Business Materials Auto-Fill）

> 适用场景：用户上传商务信息文档（.docx/.pdf，内容为营业执照、资质证书、人员证件、业绩合同、社保记录、企业能力证书等）时，自动把文档中的**文本+图片**按内容类型插入到投标文件框架的对应章节，并保持 skill 格式规范。

## When to Use

- 用户说「把这个/这份文档的内容贴到标书对应位置」「帮我填充商务部分」「上传了商务材料，放进投标文件」
- 输入的商务文档通常是一个「材料打包 docx」：内部按标题分组（如"陈刚SJ2203 劳动合同 / 身份证 / 职称证书 / 学历证书 / 企业法人营业执照 / 工程设计资质证书 / 呼和浩特市交通运输服务中心…合同"），每组标题后跟若干页扫描图片。

## Step 1: 提取文档文本与图片

1. 文本：用 `extract_docx_text(filePath=...)` 提取全文，识别文档内的分组标题（如"劳动合同""身份证""职称证书""学历证书""企业法人营业执照""工程设计资质证书""合同扫描件"）。
2. 图片：docx 本质是 zip，用 `zipfile` 解包 `word/media/` 目录，导出全部内嵌图片（通常命名 image1.png, image2.png …）。
3. 图片顺序：读 `word/document.xml` 与 `word/_rels/document.xml.rels`：
   - 建立 `rId → media/文件名` 映射；
   - 按文档流顺序遍历段落，段落含 `r:embed="rIdN"` 则为图片段，含 `<w:t>` 则为文本段；
   - 从而得到「标题 → 图片」的真实分组（文档流顺序 = 图与文的先后关系），不要只按文件名猜测归属。

## Step 2: 图片压缩（控制 docx 体积）

扫描件 PNG 单张常达 0.4~2.3MB，27 张约 20MB，不压缩会导致最终 docx 超过平台上传限制。

- 用 Pillow（PIL）压缩：`Image.open` → RGBA/P 转 RGB（透明 PNG 转白底，防变黑）→ 最长边限制 1600px（`LANCZOS`）→ `save("xxx.jpg", "JPEG", quality=82, optimize=True)`。
- 全部商务图输出到 `figs/biz_jpg/`（统一 jpg），压缩后通常 20MB → 3MB（约 17%）。
- 技术架构图（figs/png/*.png）保持原样，不压缩。

## Step 3: 章节-材料映射表（插入位置）

| 材料类型 | 插入章节 | 插入形式 |
| --- | --- | --- |
| 企业法人营业执照 | 14.1 资格审查资料-基本条件 | 「企业法人营业执照（扫描件）：」标题 + 图片 |
| 工程设计/其他资质证书 | 14.1 资格审查资料-基本条件 | 「工程设计资质证书（扫描件）：」标题 + 图片 |
| 劳动合同 | 14.1 基本条件-人员材料 + 27 社保缴费记录 | 「劳动合同（扫描件）：」+ 图片 |
| 身份证 | 14.1 人员材料 | 「身份证（扫描件）：」+ 图片 |
| 职称证书 | 14.1 人员材料 | 「职称证书（扫描件）：」+ 图片 |
| 学历证书 | 14.1 人员材料 | 「学历证书（扫描件）：」+ 图片 |
| 业绩合同扫描件 | 14.4 资格审查资料-业绩要求 + 26 业绩情况表 | 「XX项目合同（扫描件）：」+ 图片（26 章可放前 1~3 张示意） |
| 社保缴费记录 | 27 社保缴费记录 | 扫描图片 |
| 质量/信息安全体系认证、软著 | 31 企业能力 | 证书扫描图片 |

映射规则：
- 同类型材料归入同一章节下，用加粗小标题分隔（如 `**企业法人营业执照（扫描件）：**`），图片紧随其后。
- 人员证件类（劳动合同/身份证/职称/学历）在 14.1 放在「项目人员材料（陈刚 SJ2203）」小节下；同时可在 27 章补一句说明（如"已提供人员证件材料，社保凭证待人力/财务补充"）。
- 业绩合同在 14.4 全部放；26 章表格中登记合同信息（项目名称/甲方/金额/时间），金额与时间未知填 `待补充`，并保留"资格要求3项，已提供1项，需再补2项"的注记。

## Step 4: 插入 md 与渲染 docx

1. 在 `tender_full_merged.md`（或对应分册 md）的目标章节锚点（如 `**已提供材料：**` 段之后、`### 14.2` 之前）插入：
   ```
   **企业法人营业执照（扫描件）：**
   
   ![企业法人营业执照1](figs/biz_jpg/image11.jpg)
   ![企业法人营业执照2](figs/biz_jpg/image12.jpg)
   ```
   图片引用格式：`![图题](相对路径)`，路径相对工作区根目录，图片必须真实存在（渲染前校验 `os.path.exists`）。
2. 渲染：用 md2docx_skill 的 custom 模式渲染整个投标文件 docx（保留目录、分页符、黑体标题/宋体正文小四/1.5倍行距/首行缩进、表格五号字）。
3. 目录不需要手工维护——脚本自动按 Heading 层级生成；新增章节标题会自动进入目录。

## Step 5: 验证（必须做）

- 用 python-docx 打开生成后的 docx，按「正文标题样式（Heading 2/3）」定位 14.1、14.4、26、27 等章节的真实段落区间（**跳过目录区**——目录区段落样式不是 Heading 2/3 正文标题，或位于文档前部）。
- 对每个目标章节区间，统计含 `<w:drawing>` 的段落数，确认图片数量符合预期（如 14.1=14张、14.4=13张、26=3张）。
- 检查 `word/media/` 内嵌图片总数 = 技术图 + 商务图。
- 检查章节 1-50 无缺失、分页符数量、文件体积（压缩后应 <10MB，最好 <5MB）。
- 把生成的 docx 用文件写入方式放到工作区根目录（open().write() 或 shutil.copy 到可下载目录），确保返回的下载链接指向最新文件——**直接改 /app/data/workspace 下的同名文件可能不刷新下载链接，需写新文件或写工作区根目录**。

## Gotchas

- **图片归属必须看 document.xml 的 r:embed 顺序**，不能靠文件名猜；一个段落可含多张图（如身份证两页并排）。
- **透明 PNG 直接转 JPG 会变黑**：先转 RGB 并铺白底。
- **压缩后记得更新 md 里的图片路径**（figs/biz/image1.png → figs/biz_jpg/image1.jpg），并校验所有引用路径存在，否则渲染脚本会输出「[图片缺失: xxx]」占位文本。
- **渲染超时**：大 md（30万+字符）+ 大图时，用 subprocess 调 md2docx_skill.py 并给足 timeout（280~300s），不要用 importlib 内联跑（容易 30s 超时）。
- **下载链接不刷新**：文件写回原路径时平台可能返回旧缓存链接；解决：写新文件名或复制到工作区根目录，取新生成的 generatedFiles 链接。
- **材料缺口如实标注**：只有 1 份业绩就写"已提供1项，需再补2项"；没有社保凭证就写"待补充"，不编造。

## 交付时向用户说明

- 每种材料放到了哪个章节（表格列出）。
- 文档体积（压缩前后对比）。
- 仍需人工补充的缺口（缺的业绩、社保凭证、公章等）。
- 提供最终 docx 下载链接 + 可编辑 md 源文件链接。
