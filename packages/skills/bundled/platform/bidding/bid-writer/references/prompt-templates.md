# Prompt Templates

Use these templates as building blocks. Adapt wording to the user's materials, assigned scope, target section, and output needs.

Core design pattern for every step:

```text
角色：明确你在这一步扮演谁。
任务：明确这一步只做什么，不做什么。
输入：明确需要读取哪些文件、表格、历史稿或用户说明。
输出：明确必须输出哪些表、清单、正文或审核结论。
约束：明确不得编造、不得越界、不得跳步、哪些事项要人工确认。
下一步：说明用户下一步需要提供或确认什么。
```

## 1. 确认任务范围

```text
你是一名资深投标项目顾问。请先根据我提供的材料和说明，帮我确认本次标书任务范围，不要直接写正文。

输入材料：
- 招标文件：
- 投标文件框架：
- 历史参考稿：
- 公司素材：
- 我负责的章节：
- 我不负责的章节：
- 页数 / 格式 / 文件命名要求：

请输出：
1. 本次需要完成的章节；
2. 我负责、他人负责、仅作参考、暂不处理的范围；
3. 必须读取或参考的材料；
4. 当前缺失或需要确认的信息；
5. 下一步建议先分析哪些文件。

要求：
- 不要默认我负责整份标书；
- 如果责任范围不清楚，先列出需要我确认的问题；
- 区分"已明确的信息"和"待确认的信息"；
- 每一步结束后都提示：这一步做了什么、得到什么结果、我下一步需要提供或确认什么。
```

## 2. 建立责任边界

```text
你是一名投标项目协同顾问。请根据任务范围、目录和分工信息，建立责任边界表，不要开始写正文。

请按表格输出：
| 章节 / 内容项 | 责任归属 | 与我负责内容的关系 | 我需要获取的信息 | 我需要交付给他人的内容 | 风险或待确认事项 |

责任归属只能使用：
- 我负责
- 他人负责
- 仅作参考
- 暂不处理

要求：
- 如果我只负责技术部分、单个章节或部分小节，只围绕这些范围展开；
- 商务、报价、法务、资质、人员证书、业绩证明等范围外内容，只做关联提醒，不代写；
- 如果我的章节依赖其他章节，请明确"需要协同"或"需要上游输入"；
- 输出最后给出"下一步：分析写作风格"。
```

## 3. 分析写作风格

```text
你是一名标书写作风格分析顾问。请先分析我提供的历史稿、参考稿或用户认可版本，再提出大纲建议。

请输出：
1. 参考稿的标题层级特点；
2. 正文段落密度；
3. 表格和图示使用比例；
4. 常用表达方式和语气；
5. 不建议模仿或需要避免的问题；
6. 对本次章节写作的风格建议。

要求：
- 优先参考用户认可的历史稿，不要套用通用 AI 标书结构；
- 判断标题是否过碎，段落是否过短，表格是否过多；
- 如果参考素材不属于同类项目，说明哪些可以借鉴，哪些不能直接照搬；
- 输出最后给出"下一步：设计章节大纲"。
```

## 4. 设计章节大纲

```text
请根据响应矩阵、评分点、硬性要求和参考稿风格，为我负责的目标章节设计正文大纲。

输入：
- 目标章节：
- 固定标题 / 编号：
- 页数要求：
- 评分点：
- 风格参考：

请输出：
| 建议标题 | 写作重点 | 对应评分点/要求 | 需要材料 | 风险提示 | 是否建议配图/表 |

要求：
- 大纲必须覆盖所有范围内关键评分点和硬性要求；
- 保留已有章节编号和固定标题，但不要在标题文本里手写自动编号；
- 控制标题颗粒度，避免很多小标题只写 1-2 短段；
- 标题要自然、专业、简洁，避免"XXX与XXX""XXX和XXX"这类 AI 味标题；
- 如果某个标题下无法写出充分正文，应合并到更大的标题；
- 如果流程图、责任流、进度路径、风险纠偏图确实有助说明，可建议使用 image2；不要为了装饰或凑页数硬加。
```

## 5. 编写正文内容

```text
你是一名资深投标文件撰写顾问。请基于已确认的大纲、评分点、响应矩阵、招标要求和参考风格，撰写我负责章节的正文。

写作要求：
1. 只撰写我负责的章节，不代写商务、报价、法务、资质或其他人负责内容；
2. 主语使用"我司"；
3. 内容围绕评分点和硬性要求展开；
4. 语言专业、稳健、真诚，体现投标人服务诚意；
5. 不得编造未提供的公司资质、案例、人员、系统、数据或承诺；
6. 不要出现"根据招标文件""依据招标文件要求""详见招标文件""招标文件第 X 条"等索引式表达；
7. 每个标题下正文要充分展开，避免只有 1-2 个短段；
8. 不要用重复表格、重复段落或碎标题凑页数；
9. 如果资料不足，先标注"待补充素材"或"需人工确认"，不要自行编造；
10. 如果需要配图，只有在图能说明流程、进度、责任、风险或交付闭环时才使用 image2。

输出格式：
- 章节标题；
- 正文内容；
- 已响应评分点；
- 待补充素材；
- 依赖其他章节 / 他人材料；
- 风险提示。
```

## 6. 自查与交付

```text
请对已完成的投标章节进行自查，确保质量达标后移交给合规审查员。

请输出自查清单：
| 检查项 | 状态 | 说明 |

检查项包括：
1. 评分点覆盖率（X/Y 已覆盖，未覆盖项列出）；
2. 硬性要求覆盖（X/Y 已覆盖，未覆盖项列出）；
3. 幻觉/无依据内容（有/无，如有列出位置）；
4. 过度承诺（有/无，如有列出位置）；
5. 索引式表达（有/无，如有列出位置）；
6. 重复内容（有/无，如有列出位置）；
7. 标题编号（正确/有误，如有误列出位置）；
8. 页数要求（满足/不满足）；
9. 配图必要性（合理/过多/过少）；
10. 越界内容（有/无，如有列出位置）。

最后给出交付结论：
- 可移交合规审查
- 需补充后移交
- 存在高风险，暂不移交
```

## Full Execution Prompt

```text
使用 $bid-writer，帮我编写这份标书中我负责的章节。

请严格按 6 步推进，每一步都记录：
1. 这一步做了什么；
2. 得到了什么结果；
3. 我下一步需要提供或确认什么。

要求：
- 先确认范围，不要直接写正文；
- 写正文前先确认大纲和评分点；
- 写正文时参考我提供的历史稿风格；
- 写完后必须执行第 6 步自查；
- 如果存在缺材料或需人工确认事项，不要直接标记为可移交。
```
