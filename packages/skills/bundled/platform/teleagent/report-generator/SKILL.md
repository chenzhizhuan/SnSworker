# 职场汇报文档生成器

将零散的工作要点转化为结构清晰、数据化、老板爱看的日报/周报/月报。

## 工作流

1. **确认信息**：判断用户提供的信息是否足够生成完整报告。不足则追问（缺少哪些维度见下方模板）。
2. **选择模板**：根据用户需求选择日报 / 周报 / 月报模板。
3. **填充内容**：将用户提供的信息映射到模板结构中，必要时主动归类、量化、提炼。
4. **输出交付**：生成最终文档，默认输出 Markdown，可按需输出为 Word (.docx) 或腾讯文档。
5. **自动归档**：将生成的工作日志自动保存到 `D:/工作日志` 目录（见下方归档机制）。
6. **记忆同步**：将本期工作事项同步写入长期记忆 daily-log，便于后续检索回顾（见下方记忆同步机制）。
7. **计划征询**：报告生成后主动询问下一期工作计划（见下方计划征询机制）。

## 核心原则

- **不编造内容**：用户没提的工作事项绝不凭空添加，但可以主动归纳归类。
- **结构优先**：统一使用模板结构，让报告格式稳定、易读。
- **量化表达**：鼓励用数字说话（完成数、进度百分比、对比数据）。
- **简洁有力**：不堆砌套话，每条工作项控制在 1 句话。
- **主动润色**：用户给出的口语化描述，转为书面化、专业化的表达。
- **日报一页原则**：日报必须控制在一页内（约 20 行 / 500 字以内），每条事项一句话概括，合并"今日完成"与"进行中"为"今日工作"，省略无内容章节。

## 模板

详见 [references/templates.md](references/templates.md)，包含日报、周报、月报三套标准模板。

### 模板速览

**日报**：今日工作（合并完成+进行中）→ 明日计划 → 需要支持（一页内）

**周报**：本周工作总结（分类）→ 数据/成果 → 问题与风险 → 下周计划

**月报**：月度综述 → 重点成果（项目维度）→ 数据指标 → 问题与改进 → 下月规划

## 交互策略

| 场景 | 处理方式 |
|------|---------|
| 用户给了完整信息 | 直接生成报告，不追问 |
| 信息明显缺失关键项 | 一次性追问缺失项（不逐条问） |
| 用户只给了关键词/碎片 | 先整理已知信息，再标注缺失项，请用户补充 |
| 用户要求特定格式 | 按要求输出（Word / 腾讯文档 / 纯文本） |
| 用户想修改已生成的报告 | 直接修改，不重头来 |

## 输出格式

- **默认**：Markdown（即时预览）
- **Word**：调用 docx skill 生成 .docx 文件
- **腾讯文档**：调用 qclaw_tdoc_mcp_call 创建智能文档
- 用户未指定格式时默认 Markdown，仅在用户要求时使用其他格式

## 工作日志自动归档

每次生成日报/周报/月报后，**必须**将报告自动归档到本地工作日志目录。

### 归档路径

```
D:/工作日志/
├── 日报/
│   ├── 2026-07-08.md          # 日报（Markdown）
│   ├── 2026-07-09.md
│   └── ...
├── 周报/
│   ├── 2026-W27.md            # 周报（按ISO周次）
│   ├── 2026-W28.md
│   └── ...
├── 月报/
│   ├── 2026-07.md             # 月报
│   ├── 2026-08.md
│   └── ...
└── Word版/
    ├── 日报-2026-07-08.docx   # Word格式日报
    ├── 周报-2026-W27.docx
    └── ...
```

### 归档规则

1. **自动创建目录**：若 `D:/工作日志` 或其子目录（日报/周报/月报/Word版）不存在，自动创建。
2. **文件命名**：
   - 日报：`YYYY-MM-DD.md`（如 `2026-07-08.md`）
   - 周报：`YYYY-WNN.md`（如 `2026-W27.md`，NN为ISO周次）
   - 月报：`YYYY-MM.md`（如 `2026-07.md`）
   - Word版：`报告类型-YYYY-MM-DD.docx` 或 `报告类型-YYYY-WNN.docx`
3. **永不覆盖**：若同名文件已存在，在文件名末尾追加 `-v2`、`-v3` 等版本号，如 `2026-07-08-v2.md`。
4. **双格式归档**：
   - Markdown版：始终归档到对应的子目录（日报/周报/月报）
   - Word版：仅当用户明确要求生成 Word 格式时，额外归档到 `Word版/` 子目录
5. **归档时机**：在向用户展示报告内容后、回复结束前，执行归档写文件操作。
6. **归档确认**：归档完成后，在回复中简要告知归档路径，如"已归档至 D:/工作日志/日报/2026-07-08.md"。

### 归档内容

- Markdown版本：完整的报告正文内容（不含 AIGC 水印）
- Word版本：与用户收到的 Word 文件内容一致
- 每份归档文件**末尾**追加元数据注释：

```markdown
---
归档时间: YYYY-MM-DD HH:mm
报告类型: 日报/周报/月报
生成工具: report-generator skill
```

## 工作任务记忆同步

每次生成日报/周报/月报后，**必须**将本期工作事项同步写入长期记忆的每日日志，使工作记录可被后续检索和回顾。

### 同步规则

1. **写入目标**：长期记忆 daily-log 目录下的当日日志文件（`daily-log/YYYY-MM-DD.md`，相对于记忆根目录）。
2. **写入时机**：在归档完成后、回复结束前执行。
3. **写入格式**：在当日日志中追加一条结构化记录：

```markdown
- [YYYY-MM-DDTHH:mm:ss.SSSZ] 生成{日报/周报/月报}，工作内容：
  - {工作事项1}
  - {工作事项2}
  - ...
  归档路径: {归档文件路径}
```

4. **增量追加**：若当日日志已存在，在末尾追加；不存在则新建。
5. **内容精简**：每条工作事项用一句话概括，与报告正文保持一致，不展开细节。
6. **不重复写入**：同一次报告中仅写入一次，若用户多次修改报告，仅在首次生成时写入记忆。

## 计划征询机制

报告生成并归档后，**必须**主动询问用户下一期的工作计划，以便持续衔接工作节奏。

### 征询规则

| 报告类型 | 征询内容 | 示例话术 |
|---------|---------|---------|
| 日报 | 询问明日工作计划 | "明天有什么工作计划？可以告诉我，我帮你一并整理到日报的'明日计划'中。" |
| 周报 | 询问下周工作计划 | "下周有什么重点工作安排？可以提前说一下，我帮你补充到周报的'下周计划'里。" |
| 月报 | 询问下月工作规划 | "下个月有什么重点工作规划？可以提前说，我帮你完善到月报的'下月规划'中。" |

### 征询时机与方式

1. **时机**：在报告内容展示完毕、归档路径告知之后，作为回复的收尾环节提出。
2. **方式**：使用 `question` 工具发起询问，提供"直接输入计划"和"暂时没有计划"两个选项。
3. **回填逻辑**：
   - 用户提供了计划 → 将计划内容回填到当前报告的"明日计划/下周计划/下月规划"章节，更新归档文件和记忆日志。
   - 用户选择"暂时没有" → 不回填，正常结束回复。
4. **不强制**：用户可跳过此环节，不回答也不影响报告生成。
