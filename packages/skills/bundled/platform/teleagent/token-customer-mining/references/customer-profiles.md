# 7 类目标客户画像详解

> **核心前提**：Token 是大模型 API 替换服务。以下 7 类客户必须是【已有 AI 应用、正在调用外部大模型 API】的企业。

---

## A 类：AI 开发商 / AI 行业软件企业

### 核心特征
- 公司名含"智能""AI""大模型""算法"
- **已有 AI 产品上线**（SaaS/平台/API 服务），正在对外提供 AI 能力
- 有算法/NLP 工程师团队，产品已商用
- 每月 Token 消耗量大（10 万+），对 API 成本敏感

### AI 使用信号（必须满足至少 1 项）
- 产品页面/官网展示 AI 功能（智能客服、AI 助手、智能分析等）
- 招聘信息中有大模型/LLM/算法工程师/NLP 岗位
- 融资新闻提到 AI/大模型方向
- 技术博客/GitHub 提到 OpenAI/文心/通义等 API 调用
- 新闻报道提到"接入大模型""AI 产品发布"

### 当前 API 供应商判断
- 产品文档中提到 OpenAI/百度文心/阿里通义/DeepSeek/智谱
- 招聘信息要求有 OpenAI/LLM API 对接经验
- 产品定价页提到"按 token 计费"

### Token 替换价值
- **降本**：API 调用量大，替换后成本显著降低
- **多模型统一管理**：一个接口调用多个模型
- **稳定性**：天翼云提供高可用保障

### 切入话术
> "你们的 AI 产品现在调用的是哪家的大模型 API？每月 token 消耗量级多少？天翼云提供兼容接口，替换 endpoint 就行，代码几乎不用改，而且成本更优、稳定性有保障。"

### 搜索关键词
- `{城市名} 招聘 大模型 LLM 算法工程师`
- `{城市名} AI产品 智能客服 AI助手 上线`
- `{城市名} 人工智能 融资 AI创业`
- `{城市名} AI SaaS 大模型 平台`

---

## B 类：自建 AI 应用 / 智能体的企业

### 核心特征
- 中大型企业（50 人以上），有 IT 部门或信息化团队
- **已内部部署 AI 工具**（智能客服、AI 知识库、AI 助手、智能审批等）
- AI 工具正在调用外部大模型 API 运行
- 员工已在使用 AI（可能是各部门各自采购，管理混乱）

### AI 使用信号（必须满足至少 1 项）
- 招聘信息中有"大模型应用开发""AI 平台建设"岗位
- 新闻/官网提到"上线 AI 助手""部署智能客服""AI 知识库"
- 企业公众号/内刊提到员工使用 AI 工具
- 招聘 prompt 工程师/AI 运营岗位
- 数字化转型新闻中提到 AI 应用部署

### 当前 API 供应商判断
- 招聘信息要求有 DeepSeek/智谱/文心 API 对接经验
- 企业技术分享提到大模型 API 调用
- AI 产品功能描述中提到底层模型

### Token 替换价值
- **降本**：内部 AI 工具持续消耗 token
- **统一管理**：各部门 AI 使用集中管理、统一计费
- **合规**：国企/央企有信创要求，天翼云满足国产化

### 切入话术
> "你们内部的 AI 工具现在调用的是哪家的大模型？各部门是统一采购还是各自买的？天翼云可以提供统一 API 接口，一个账号管所有模型调用，成本透明、管理统一。"

### 搜索关键词
- `{城市名} 企业 AI助手 智能客服 上线 部署`
- `{城市名} 招聘 大模型应用 AI平台 prompt`
- `{城市名} 数字化 AI知识库 智能问答 运行`
- `{城市名} 企业内部 AI工具 应用`

## C 类：已有 AI 应用的制造企业

### 核心特征
- 年营收 ≥ 2000 万元的制造业企业
- **已上线 AI 应用**：智能客服（售后）、AI 知识库（工艺/质检/培训）、AI 质检等
- AI 应用正在调用外部大模型 API
- 有 IT 部门或与外部技术供应商合作

### AI 使用信号（必须满足至少 1 项）
- 新闻提到"上线智能客服""部署 AI 知识库""AI 质检系统"
- 招聘信息中有 AI/大模型相关岗位
- 供应商案例中提到该企业使用了 AI 应用
- 企业公众号报道 AI 应用成效
- 招标信息中已有 AI 相关采购记录

### 当前 API 供应商判断
- AI 应用供应商案例中提到底层模型
- 招标文件中指定大模型 API
- 企业技术人员分享中提到 API 调用

### Token 替换价值
- **降本**：售后客服 AI 7x24 小时运行，调用量大
- **稳定性保障**：生产环境需要高可用
- **统一管理**：多个 AI 应用统一接口

### 切入话术
> "你们的智能客服/AI 知识库现在用的是哪家的大模型 API？一个月调用量大概多少？天翼云可以提供兼容接口替换，不停机切换，成本更优，而且有电信级稳定性保障。"

### 搜索关键词
- `{城市名} 制造业 智能客服 AI知识库 上线 运行`
- `{城市名} 工业AI 质检 智能问答 大模型 应用`
- `{城市名} 制造企业 AI 智能化 案例`
- `{城市名} 工厂 AI助手 部署 在用`

### 注意事项
- **排除**：只有"智能化改造"规划但还没上 AI 应用的企业
- **排除**：数据涉密的军工制造企业
- **保留**：金融科技子公司做 AI 的（母公司可能排除，但子公司可以）

## D 类：已用 AI 的跨境电商 / 外贸企业

### 核心特征
- 年出口额 1000 万以上的外贸企业
- **已在用 AI 工具**：AI 翻译、AI 文案生成、AI 智能客服
- 运营团队在用 ChatGPT/DeepSeek 等工具处理日常多语言内容
- 有运营团队 5 人以上

### AI 使用信号（必须满足至少 1 项）
- 招聘信息要求会使用 ChatGPT/AI 工具
- 企业分享/培训中提到 AI 工具使用经验
- 运营岗位 JD 中提到"AI 辅助""ChatGPT""AI 文案"
- 新闻报道提到企业用 AI 做跨境营销
- 企业公众号分享 AI 使用心得

### 当前 API 供应商判断
- 招聘信息提到 OpenAI/ChatGPT 经验
- 企业分享中提到具体 AI 工具
- 运营团队在用 DeepSeek/文心等国内 API

### Token 替换价值
- **降本**：多语言翻译/文案生成调用量大
- **合规**：OpenAI 在国内有合规风险，天翼云提供合规替代
- **稳定性**：跨境业务需要 7x24 稳定 API

### 切入话术
> "你们做跨境，翻译和文案现在用的是 ChatGPT 还是国内的大模型？OpenAI 在国内用也有合规风险。天翼云提供兼容接口，翻译和文案生成的代码不用改，直接替换 endpoint，合规又稳定。"

### 搜索关键词
- `{城市名} 跨境电商 AI翻译 AI文案 在用 招聘`
- `{城市名} 外贸 ChatGPT AI 工具 应用`
- `{城市名} 跨境 AI智能客服 多语言 在用`
- `{城市名} 电商运营 AI 招聘 ChatGPT DeepSeek`

### 注意事项
- **排除**：还没用 AI、纯人工翻译的外贸企业
- **保留**：即使只是运营人员在用 ChatGPT，也是目标客户（可做企业级 API 替换）

## E 类：已用 AI 编码的软件企业

### 核心特征
- 软件开发团队 ≥ 10 人
- **团队已在用 AI 编码工具**：GitHub Copilot、Cursor、ChatGPT 辅助编码
- 有后端工程师团队，能做 API endpoint 替换
- 业务：软件外包、SaaS 产品、系统集成、互联网平台

### AI 使用信号（必须满足至少 1 项）
- 招聘信息提到"熟悉 Copilot/Cursor/AI 编码"
- 技术博客/分享中提到 AI 编码工具使用
- 企业介绍中提到"AI 辅助开发"
- 开发岗位 JD 中要求"会使用 AI 工具提效"
- GitHub 仓库中有 AI 相关代码

### 当前 API 供应商判断
- 在用 GitHub Copilot（背后是 OpenAI API）
- 在用 Cursor（背后是 OpenAI/Anthropic API）
- 在用自建 AI 编码助手（调用外部 API）
- 在用 ChatGPT API 做代码生成

### Token 替换价值
- **降本**：Copilot/Cursor 订阅费用高，API 替换更灵活
- **统一管理**：团队 AI 编码工具统一管理
- **数据安全**：代码不出企业，通过天翼云 API 中转

### 切入话术
> "你们开发团队现在用的是 Copilot 还是 Cursor？每月订阅费用不低吧。天翼云可以提供兼容 API，你们自己做或用开源 AI 编码工具对接，成本更可控，代码数据走天翼云也安全。"

### 搜索关键词
- `{城市名} 软件开发 Copilot Cursor AI编码 招聘`
- `{城市名} 程序员 AI编程 在用 ChatGPT 代码`
- `{城市名} 软件企业 AI辅助开发 工具`
- `{城市名} 开发团队 AI编码 大模型 效率`

### 注意事项
- **排除**：还没用任何 AI 编码工具的软件企业
- **保留**：即使只有部分团队在用 Copilot，也是目标客户

### 核心特征

- **已上线 AI 实训平台**，学生在用
- AI 实训平台正在调用外部大模型 API
- 有信息中心/网络中心技术团队

### AI 使用信号（必须满足至少 1 项）
- 院校官网提到"AI 实训平台上线"
- 招标信息中已有 AI 实训平台采购
- 新闻报道学生使用 AI 实训
- 招聘信息中有 AI 实训教师/平台运维岗位
- 院校与 AI 企业合作共建实训基地

### 当前 API 供应商判断
- 实训平台供应商案例中提到底层模型
- 招标文件中指定大模型 API
- 实训平台功能描述中提到模型

### Token 替换价值
- **降本**：学生实训调用量大
- **信创合规**：院校有信创要求，天翼云满足国产化
- **统一管理**：实训平台统一 API 管理

### 切入话术
> "咱们学校的 AI 实训平台现在调用的是哪家的大模型 API？学生实训调用量应该不小。天翼云可以提供国产化 API 接口，信创合规，而且有教育行业专属方案。"

### 搜索关键词
- `{城市名} 高职院校 AI实训 大模型 平台 上线`
- `{城市名} 职业技术学院 人工智能 实训 招标`
- `{城市名} 院校 AI 大模型 教育 应用`
- `{城市名} 高职 AI实验室 智慧教育 在用`

### 注意事项
- **排除**：有 AI 专业但还没上线 AI 实训平台的院校
- **排除**：涉密/国防类院校
- **保留**：只要 AI 实训平台已上线运行即可

## 排除清单（绝对不能出现在清单中）

### 1. 涉密/军工/国安类
- 企业名称含"军工""国防""安全""保密""航天科工""兵器"等
- 涉及国家安全的企业
- 军工配套涉密企业

### 2. 政府核心部门
- 公安/国安/海关/税务核心系统
- 政府涉密信息系统
- 党政机关核心办公系统（数据不能出外网）

### 3. 金融核心系统
- 银行核心账务系统
- 证券交易核心系统
- 保险核心业务系统
- 注意：金融科技子公司做 AI 产品的**可以保留**

### 4. 医疗核心数据系统
- 电子病历系统
- 患者数据平台
- 医疗影像诊断核心系统
- 注意：医院信息化部门做 AI 应用的**可以保留**

### 5. 无 AI 应用确认
- 搜索结果中没有任何 AI 使用信号
- 只有"数字化转型规划"但没有实际 AI 部署
- 只有"智能化改造"规划但没有 AI 应用上线

### 6. 数据必须完全本地化
- 明确要求数据不能出内网的企业
- 需要私有化部署而非 API 替换的企业
- 数据安全等级要求高于公有云 API 的场景
