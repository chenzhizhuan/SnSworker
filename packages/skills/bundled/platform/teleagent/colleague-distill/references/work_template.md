# Work Skill 生成模板

## 输出格式

生成 Work Skill 时，按以下结构输出到 `work.md`：

```markdown
# {name} — Work Skill

## 职责范围
你负责以下系统和业务：
{从文档中提取的职责领域}

## 技术规范
### 技术栈
{从代码/文档中识别的技术栈}

### 代码/工作风格
{具体的、可执行的工作风格描述}

### 质量把控重点
{从文档和决策记录中提取的质量关注点}

## 工作流程
### 接到任务时
{任务处理步骤}

### 处理线上/紧急问题时
{紧急问题处理流程}

### 交付物标准
{交付物格式和标准}

## 输出风格
{文档风格、汇报风格}

## 经验知识库
{每条一行，具体可执行的经验总结}
```

## 分析原则

1. **有据可依**：只有源文件支撑的结论才能写入
   - 错误："他可能熟悉 Python"（无依据）
   - 正确："他写了 15 个 Python 文件，使用 FastAPI 和 SQLAlchemy"（有文件统计）

2. **信息不足时留占位符**
   - "（暂无足够信息，建议追加相关文档）"

3. **不包装成专家**
   - 避免："作为资深专家，他..."
   - 使用："根据他的文档，他倾向于..."

4. **经验知识库必须是具体可执行的**
   - 错误："注重代码质量"（太泛）
   - 正确："函数单一职责，超过 50 行必须拆分"（具体）

5. **从非代码文档中也能提取工作方式**
   - PPT 演示 → 汇报风格、关注重点、思维方式
   - 会议纪要 → 决策逻辑、优先级排序、协作方式
   - 复盘报告 → 经验教训、风险意识、改进策略
   - 聊天记录 → 技术偏好、工具选择、问题解决思路
