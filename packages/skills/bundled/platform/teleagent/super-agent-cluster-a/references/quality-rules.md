## 五维质检评分标准

### 事实准确性（权重0.30）— 核心数据来自[Agent-核查型]

| 得分 | 标准 | 数据来源 |
|------|------|---------|
| 1.0 | 全部断言与来源一致，数据精确 | 数字回溯全通过 |
| 0.8 | 偏差小于5%且已标注差异原因 | 数字回溯大部分通过 |
| 0.5 | 存在偏差5%至10%但已标注 | 部分数字回溯失败 |
| 0.0 | 偏差大于5%或核心数据与来源不符 | 数字回溯关键失败 |

### 逻辑一致性（权重0.25）— 核心数据来自[Agent-验证型]

| 得分 | 标准 | 数据来源 |
|------|------|---------|
| 1.0 | 推理链完整，结论从前提严格推出 | 逻辑谬误检测全通过 |
| 0.7 | 有小跳跃但整体逻辑成立 | 发现少量逻辑跳跃 |
| 0.3 | 存在明显逻辑跳跃但结论方向正确 | 发现明显逻辑谬误 |
| 0.0 | 推理链断裂或自相矛盾 | 发现致命逻辑谬误 |

### 来源可靠性（权重0.25）— 核心数据来自[Agent-核查型]

| 得分 | 标准 | 数据来源 |
|------|------|---------|
| 1.0 | 核心结论有2个以上独立权威来源 | 来源独立性校验全通过 |
| 0.7 | 单来源但权威 | 标注"单源权威" |
| 0.3 | 单来源且非权威 | 标注"单源非权威" |
| 0.0 | 来源缺失或来源不可追溯 | 标注"来源缺失" |

### 搜索准确性校验规则（⛔每次任务100%强制执行，不可跳过）

来源可靠性评分的基础上，[Agent-核查型]对搜索结果执行以下增量校验：

**来源分级评分**：每条引用信息按来源等级标注并影响最终得分。

| 来源等级 | 评分系数 | 说明 | 对来源可靠性得分的影响 |
|---------|---------|------|---------------------|
| T1一手来源 | ×1.0 | 官方文档/原始数据/法规 | 得分不加权扣减 |
| T2权威二手 | ×0.95 | 主流媒体/行业报告/同行评审论文 | 得分×0.95 |
| T3普通二手 | ×0.8 | 行业博客/自媒体/百科 | 得分×0.8，需T1/T2交叉验证 |
| T4低可信来源 | ×0.5 | 论坛帖/匿名评论/营销内容 | 得分×0.5，仅作线索不进结论 |

**引用完整性校验清单**：

| 校验项 | 通过条件 | 不通过处理 |
|--------|---------|------------|
| URL可达性 | 来源URL可正常访问且包含引用内容 | 标注"来源不可获取"，降级证据等级 |
| 文字一致性 | 引用的文字在来源原文中逐字存在 | 不符→标注"引用偏移"，驳回修正 |
| 数字一致性 | 引用的数字与来源原始数据逐位一致 | 不符→标注"数据偏移"，偏差>5%驳回 |
| 上下文完整性 | 引用未截取部分改变原文原意 | 标注"上下文缺失"，补充原文上下文 |
| 时间戳一致性 | 数据产出时间与结论声称时间一致 | 不一致→标注"时间偏移"，超2年标注"可能已过时" |
| 作者归属准确 | 引用观点确实来自声称的作者/机构 | 不符→标注"作者归属错误"，驳回修正 |

**防幻觉交叉校验强制规则**：[Agent-核查型]对[Agent-搜索型]返回的每条关键信息执行反向逐字比对——将返回的数字/事实/结论回原来源逐字查找。完全找不到→标注"疑似幻觉"，删除该条信息并触发重新搜索。部分偏移>5%→标注"数据偏移"，驳回修正。来源存在但Agent解读错误→标注"解读偏差"，要求重新解读。

**搜索验证门禁**：Swarm阶段收敛判定前必须通过以下4项门禁（缺一不可，未通过→追加补搜，不可跳过进入Verify）：

| 门禁项 | 通过条件 | 不通过后果 |
|--------|---------|------------|
| 来源覆盖率 | 每个核心结论至少1条可追溯T1/T2来源 | 追加补搜至全部覆盖 |
| 来源多样性 | 核心结论≥2种来源类型（不可全部同站/同作者） | 追加不同类型来源补搜 |
| 时间戳验证 | 数据时间与声称时间一致或已标注时效性警告 | 超期未标注→补标警告 |
| 无幻觉标记 | 搜索返回信息与最终引用信息100%一致 | 删除幻觉条目+重新搜索 |

### 完整性（权重0.10）

| 得分 | 标准 |
|------|------|
| 1.0 | 全部要点覆盖 |
| 0.7 | 非关键要点遗漏 |
| 0.0 | 关键要点遗漏 |

### 幻觉检测（权重0.10）— 核心数据来自核查型+[Agent-综合型]

| 得分 | 标准 | 数据来源 |
|------|------|---------|
| 1.0 | 无任何虚构数据或引用 | 证据链审查+可验证性自检全通过 |
| 0.5 | 存在无法验证但合理的推断（已标注） | 部分证据链存疑 |
| 0.0 | 发现虚构数据、引用或来源 | 发现虚构信息 |

## 反趋同检测规则

### 检测触发条件

- 多个并行Agent处理同一子任务时
- 多个Agent引用了重叠的信息来源时
- 多个Agent的结论方向高度一致时

### 检测指标

| 指标 | 阈值 | 判定 |
|------|------|------|
| 关键词重合率 | 超过80% | 趋同嫌疑 |
| 来源重合率 | 超过60% | 来源依赖 |
| 结论方向一致率 | 100%无异议 | 一致性过高 |
| 独立来源数量 | 少于3个 | 交叉验证不足 |
| 来源类型覆盖 | 少于2种 | 广度不足 |

### 修正动作

- 标注趋同警告，在输出中注明
- 要求至少1个Agent更换信息来源或更换分析角度
- 主动注入反面证据，要求重新审视结论
- 反趋同修正系数从1.0降至0.9（已修正）或0.8（未修正）

## 红蓝对抗验证规则（每次任务100%强制执行）

### 适用场景

**强制执行**：红蓝对抗对每次任务的核心结论均必须执行，不论用户是否明确要求、不论置信度高低。⛔禁止以"降级到L3"或任何理由用简化自检替代完整红蓝对抗——每次任务必须执行完整对抗。

**额外加强关注场景**（以下场景除强制执行外，需额外加强红蓝对抗的深度和广度）：
- 置信度评分在0.85以上的核心结论
- 涉及投资决策、技术选型、风险评估等高影响场景
- 上述场景以外的常规结论也必须执行红蓝对抗（可用简化版）

### 执行流程

1. 红方Agent负责论证结论的正确性，收集支持证据
2. 蓝方Agent负责寻找反驳证据和逻辑漏洞，模拟质疑者
3. 裁决：只有当红方论证通过且蓝方无法找到致命反驳时，结论标记为"对抗验证通过"
4. 蓝方找到致命反驳：结论标记为"对抗验证未通过"，触发纠错循环

## 逻辑谬误猎杀规则

| 谬误类型 | 检测方法 | 处理方式 |
|---------|---------|---------|
| 滑坡谬误 | 检查推理链每步是否必然导致下一步 | 标注断裂点，要求补充中间推理 |
| 虚假二分 | 检查是否只呈现两个极端选项 | 补充中间选项 |
| 诉诸权威 | 检查是否仅因来源权威就接受结论 | 要求独立数据验证 |
| 摘樱桃谬误 | 检查是否只选择支持性证据 | 补充反面证据 |
| 事后归因 | 检查相关关系是否被错误表述为因果关系 | 标注"相关不等于因果" |

## 事实核查清单

每个结论在标记为"已验证"前，[Agent-核查型]逐项检查。核查项分为两类：**强制检查**（每个结论必须执行）和**条件触发检查**（每次任务必须评估触发条件，满足时强制执行）。

### 强制检查（15项，每个结论必须执行）

| 核查项 | 检查内容 | 不通过处理 |
|--------|---------|------------|
| 数据可追溯 | 每个数字是否有原始来源 | 无来源数字标注"未验证" |
| 因果vs相关 | 因果表述是否有证据支撑 | 相关性误表述为因果性→驳回修正 |
| 反面证据 | 是否考虑了反对观点 | 未考虑反面证据→补充搜索 |
| 事实vs观点 | 是否区分客观事实与主观判断 | 混淆事实与观点→标注区分 |
| 口径一致性 | 对比数据是否同口径 | 不同口径直接对比→标注口径差异 |
| 逻辑谬误 | 是否存在滑坡/虚假二分/诉诸权威 | 发现逻辑谬误→交由[Agent-验证型]处理 |
| 置信度计算 | 置信度是否基于公式计算 | 主观估计置信度→重新计算 |
| 利益冲突 | 来源发布方是否与结论主题存在利益关系 | 存在利益冲突→降级可信度并标注 |
| 可证伪性 | 结论是否可被证伪且暂未被证伪 | 不可证伪→降级为"理论推测" |
| 来源可获取性 | 来源URL是否可达且引用内容真实存在 | URL不可达→标注"来源不可获取" |
| 时间线一致性 | 因果倒置/时间不可能/时间窗口不重叠 | 检测到→标注时序矛盾类型 |
| 数字内部一致性 | 部分之和不等于总量/百分比与绝对数矛盾 | 检测到→标注内部一致性矛盾 |
| 来源动机与议程 | 商业推广/政策推动/流量获取/议程设置 | 检测到→降级可信度并标注动机 |
| 来源间抄袭与重叠 | n-gram重合>0.3/语义余弦>0.7 | 重叠>0.7→不视为独立来源 |
| 对比框架公平性 | 口径不一致/基准不同/条件不可比 | 不公平→标注"对比口径不一致" |

### 条件触发检查（16项，每次任务必须评估触发条件，满足时100%强制执行）

| 核查项 | 触发条件 | 检查内容 | 不通过处理 |
|--------|---------|---------|------------|
| D-S证据融合 | 多源证据需融合时 | 信念区间宽度是否可接受 | 区间宽度>0.3→标注"证据不足" |
| 统计功效 | 涉及统计推断时 | 样本量和功效是否充分 | 功效<0.8→标注"统计功效不足" |
| 来源选择偏倚 | 来源数量≥5时 | 来源集合是否存在结构偏倚 | 检测到偏倚→触发补搜或去偏 |
| p值操纵 | 结论含p值时 | p曲线在0.05附近是否出现尖峰 | 尖峰→标注"疑似p值操纵" |
| 数据捏造 | 数据集≥100条记录时 | 首位数字分布是否符合Benford定律 | 不符合→标注"疑似人为捏造" |
| 引用操纵 | 学术文献密集场景 | 自引率超30%/引用闭环/引用农场 | 检测到→降级可信度并标注 |
| 数据摘樱桃 | 对比类结论时 | 选择性时间窗口/子群/指标报告 | 检测到→标注摘樱桃类型 |
| 均值回归误判 | 趋势预测类结论时 | 趋势声称但一阶自相关低于0.3 | 标注"随机波动被误判为趋势" |
| Simpson悖论 | 含子群分解数据时 | 总体趋势与各子群趋势方向相反 | 标注"Simpson悖论警告" |
| 生态谬误 | 群体→个体推断时 | 分析单元与结论适用对象不在同一层级 | 标注"生态谬误风险" |
| 因果充分性 | 因果结论含混杂变量时 | 未测量混杂变量，Rosenbaum Γ<1.5 | 标注"因果结论稳健性不足" |
| AI生成内容 | 来源疑似AI生成时 | 困惑度低+突发性低+重复模式 | 疑似→降级0.2可信度 |
| 图像篡改 | 结论依赖图片证据时 | ELA分析不一致/EXIF矛盾/面部伪影 | 疑似→降级0.25可信度 |
| 非形式逻辑谬误 | 推理链≥3步时 | 滑坡/稻草人/诉诸权威/虚假二分/循环论证 | 检测到→标注谬误类型 |
| 因果过度归因 | 多因素结果单归因时 | 多路径可致同一结果但结论仅归因一条路径 | 标注"过度归因风险" |
| Agent信任度 | 低信任度Agent产出时 | 低信任度Agent产出需额外交叉验证 | 低信任度→标注并追加验证 |

## 证据强度评估

| 来源数量 | 来源等级 | 证据强度 | 使用方式 |
|---------|---------|---------|---------|
| 2个以上独立来源 | 均为高可靠性 | A级（强） | 可作为核心结论依据 |

| 1个来源 | 中低可靠性 | D级（极弱） | 仅作参考线索，不作为结论依据 |

## 幻觉防护机制

### 五层防护

| 防护层 | 机制 | 执行Agent | 检查内容 |
|--------|------|---------|---------|
| 输入层 | 来源锚定 | [Agent-搜索型] | 每个结论挂接至少1个可追溯来源，无来源断言标记为"推测" |
| 推理层 | 数字回溯 | [Agent-核查型] | 提取所有含数字句子，在来源列表中搜索原文匹配 |
| 去偏层 | 认知偏差矫正 | 去偏Agent | 系统性去偏协议执行，10类偏差全谱扫描 |
| 审计层 | 证据衰减+时序一致性 | 审计Agent | 证据时效性衰减评分和时序逻辑一致性校验 |
| 输出层 | 可验证性自检+校准 | 综合型+校准Agent | 最终扫描无来源数字、无证据因果，校准置信度 |

## 验证闭环

每个核心结论必须形成完整验证闭环，缺少任何环节即降级：

```text
结论提出 → 来源挂接（缺→降级"推测"）
        → 交叉验证（缺→标注"单源待验证"）
        → 反面检验（缺→补搜反对观点）
        → 数字回溯（缺→删除或加"约"）
        → 标记验证等级（A/B/C/D）
```

## 对抗自红队机制

[Agent-验证型]对每个核心结论自动启动自红队攻击（不论置信度高低，每次任务100%强制执行）：

| 攻击向量 | 攻击方式 | 攻击成功条件 |
|---------|---------|------------|
| 数据攻击 | 质疑核心数据准确性，找反例数据 | 找到1个直接矛盾的来源 |
| 逻辑攻击 | 检查推理链每环节是否有跳跃 | 发现1个环节无前提支撑 |
| 来源攻击 | 质疑来源独立性或可靠性 | 发现来源为同一信息转引 |
| 时效攻击 | 检查数据是否已过时 | 核心数据超2年且领域变化快 |
| 反例攻击 | 搜索与结论完全相反的案例 | 找到3个以上可信反例 |

攻击成功→降级一个置信度等级，标注"经自红队质疑"。

## DQG质量门禁

DQG是[Agent-验证型]放行结论前的最后一道门禁：

```text
DQG评分 = 五维加权得分 × 纠错系数 × 反趋同系数 × 幻觉防护系数 × 自红队系数 × 证据衰减系数 × 校准系数
```

| 门禁状态 | DQG评分 | 动作 |
|---------|---------|------|
| 通过 | 大于等于0.97 | 正常输出 |
| 有条件通过 | 0.90至0.96 | 输出但标注扣分维度 |
| 不通过 | 小于0.90 | 退回纠错循环重试（⛔禁止降级输出） |

幻觉防护系数：1.0（五层全通过）/ 0.8（1层未通过）/ 0.5（2层未通过）/ 0.0（3层及以上未通过）

自红队系数：1.0（攻击失败）/ 0.85（部分攻击成功）/ 0.7（关键攻击成功）

纠错系数：1.0（Verify阶段一次通过无纠错）/ 0.95（1轮纠错后通过）/ 0.90（2轮纠错后通过）/ 0.85（3轮及以上纠错后通过）。纠错轮次从Verify阶段首次驳回开始计数。

反趋同系数：1.0（无趋同）/ 0.9（趋同已修正）/ 0.8（趋同未修正）（定义见反趋同检测章节）

证据衰减系数：1.0（全部来源为T1/T2且数据在2年内）/ 0.95（含T3来源或部分数据超2年）/ 0.85（含T4来源或核心数据超2年）/ 0.75（核心结论仅依赖T4来源或超5年数据）。数据时效以当前日期为基准计算。

校准系数：0.9-1.1（基于历史任务实际准确率与标注置信度比值的动态计算，定义见校准验证规则）。校准系数>1.0表示历史系统性低估（实际准确率高于标注置信度），<1.0表示系统性高估。

## 贝叶斯置信度更新规则

### 更新流程

1. 先验置信度：基于五维加权公式计算初始DQG评分
2. 似然函数：每轮新证据对结论的支持/反驳强度
   - 支持证据：似然 = 1.0 / (1.0 + 驳回维度数 × 0.1)
   - 反驳证据：似然 = 0.5 / (1.0 + 驳回维度数 × 0.2)
3. 后验置信度：后验 = 先验 × 似然 / 归一化常数
4. 收敛判定：连续2轮后验置信度变化不超过0.05时判定收敛

### 更新约束

- 先验置信度下限为0.3
- 似然函数不低于0.2
- 后验置信度不低于先验 × 0.5
- 最大更新轮次为6轮

## 审计追踪规则

| 审计项 | 审计内容 | 审计标准 |
|--------|---------|--------|
| 搜索完整性 | 搜索轮次和覆盖面 | 是否满足Scatter-Gather要求 |
| 核查完整性 | 数字回溯覆盖率 | 核心数字是否全部回溯 |

## 去偏验证规则

1. 偏差扫描：对核查型和[Agent-验证型]的输出执行10类认知偏差扫描
2. 严重度评级：高严重度偏差（确认偏见、幸存者偏差、基率忽视）优先矫正
3. 去偏执行：高严重度偏差触发强制补证或重新估算
4. 效果验证：比较去偏前后结论变化，变化超过20%标注"去偏影响显著"
5. 结果输出：输出去偏报告但不做最终裁决

## 校准验证规则

1. 历史对标：检查历史任务中相同置信度等级的实际准确率
2. 校准系数计算：校准系数 = 实际准确率 / 标注置信度平均值
3. 主张依赖图检测：构建主张依赖图，检测环路和根节点脆弱性
4. 校准系数在0.9-1.1之间：正常输出；低于0.9：标注"系统性高估"；高于1.1：标注"系统性低估"

## 来源聚合偏差量化规则

1. 对每个来源追溯其引用的原始出处
2. 计算实际独立来源数（排除同一源头的转引）
3. 聚合偏差率 = 名义来源数 / 实际独立来源数 - 1
4. 偏差率超过50%：标注"来源聚合偏差警告"，降级证据等级

## 四范式验证体系

[Agent-验证型]整合核查型、去偏Agent、审计Agent和校准Agent的审查结果，形成四范式验证：

| 验证范式 | 核心关注 | 对DQG的影响 |
|---------|---------|------------|
| 事实核查 | 数字回溯、来源独立性、时效性、反事实验证等31项深度检查（15项强制+16项条件触发） | 影响事实准确性和来源可靠性 |
| 逻辑审查 | 红蓝对抗、趋同检测、逻辑谬误猎杀 | 影响逻辑一致性和反趋同系数 |
| 去偏审查 | 认知偏差全谱扫描、系统性去偏协议 | 影响反趋同系数和置信度调整 |
| 审计追踪 | 全链路审计、证据衰减、知识一致性、时序一致性 | 影响证据衰减系数 |

四范式验证全部通过方可流转至[Agent-综合型]。任一范式未通过则退回对应Agent修正。

交替规则：4轮为一个完整验证周期，**每次任务（L1-L4）必须完成至少1个完整周期**，L3+任务需完成2个完整周期，L4任务需完成3个完整周期。同一范式连续使用≥3轮时强制切换范式。
