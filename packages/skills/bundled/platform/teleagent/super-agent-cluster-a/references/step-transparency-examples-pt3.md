## 16. 多结果展开标注示例（⛔3+项结果时强制使用）

当单个步骤包含3项及以上结果/修正/发现/驳回时，必须按多结果展开规则标注，禁止将多项内容堆叠在单行中。

**规则回顾**（完整定义见SKILL.md「⛔ 步骤标注格式」章节）：

| 规则 | 说明 |
|------|------|
| 1 | 主行不放结果计数——汇总移到状态卡📝要点列 |
| 2 | 状态卡📝要点列放汇总——`核查N条→X确认/Y修正/Z驳回` |
| 3 | 每项独立一行——详情卡中每项一行：确认1/修正1/驳回1 |
| 4 | 每格≤80字——超长标注"见[阶段图标 步骤图标 步骤名]"或拆为子步骤 |
| 5 | 不同类型可分表——修正组与驳回组之间可分不同详情卡 |

14. **⛔截断标记三类区分+禁止括号（v2.0名称化版，三者严禁混用）**：三种截断/暂停场景使用不同标记，⛔严禁混用：

## 20. 扩展保护块（从SKILL.md下沉）

以下保护规则从SKILL.md顶部下沉至此，包括LLM自然截断保护、文本先行原则、强制预防、分段输出引导、搜索结果压缩注入、Crystallize文档校验等。

**⛔LLM自然截断保护**：输出受限致截断（句子在标点前断/括号引号未闭合/词断）→该步骤判已完成不可回写，恢复后注册新名称继续，首张表格首行标注"⚠️ 上一步内容因LLM输出长度限制自然截断"。

**⛔文本先行原则（防概率抢占截断）**：LLM生成步骤标注时，工具调用token概率可能抢占文本补全概率，导致表格在词中间被截断。⛔强制时序约束：①文本先行——全部表格语义完整输出后才允许发起工具调用，禁止文本流中途插入工具调用；②定界符保护——每张表格以完整语义收束（末字符须为汉字/字母/数字/右括号右引号），禁在词中间断开；③⛔负面约束——词中间截断即违规，须修正重输出该步骤。✅正例：最后一张表格完整输出→空行→工具调用。❌反例：最后一张表格在"检"字处断裂→直接工具调用。

**⛔强制预防（非建议）**：①每个表格单元格≤80字（必要字段可占满，⛔超限即格式错误）；②长表格先汇总再分批（⛔每批≤8项，超限分多步骤标注）；③枚举项独立一行禁加号拼接；④单步表格行总数≤8行（高发区≤5行），超过则精简合并，禁止靠长行硬塞；⑤工具调用前最后一张表格须语义完整收束，禁止词断即跳转工具调用。

**⛔分段输出引导规则（静默分界+工具钩子）**：连续步骤标注输出达4个时，第4个步骤完成后⛔静默分界（禁止输出"[批次N/总数M，自动续批]"文本）。静默分界后必须紧跟工具调用续批钩子，以工具调用驱动新轮次输出，⛔禁止分界后纯文本停滞。⛔工具调用返回后必续批：工具返回结果后⛔必须注册新名称续批输出新步骤标注，⛔禁止工具返回后停滞无后续步骤。此规则与SKILL.md规则12和本文件§19规则12配套。

**⛔搜索结果压缩注入（v3.4结构化升级）**：搜索结果⛔禁止全文注入步骤标注。搜索结果按以下结构化格式展示：

| 展示位置 | 格式 |
|---------|------|
| 步骤标注 | 状态卡📝要点列放核心要点（分条编号，每条≤30字） |
| 参考来源 | 详情卡追加URL分条展示行 |
| 完整内容 | 保留在工具输出中不重复贴入步骤标注，仅摘录关键数据点入标注 |

**⛔Crystallize文档校验（硬卡点）**：调generate_docx.py前对content_data每字段完整性校验——末尾缺自然结尾标点（。！？）或右括号/右引号或出现截断信号→先补全再调用，禁止截断内容入文档。

**⛔截断标记场景区分**：完整定义详见上方§19规则14，三类场景严禁混用，恢复后均注册新名称继续。

**⛔步骤名称唯一性强约束（防重复输出，v2.0名称化版）**：同一名称全任务只出现一次；中断恢复一律注册新名称继续；违反→删除重复项只保留首次。根因防护与工具调用结果回填规则详见上方规则10名称铁律、规则12格式检查、规则15回填名称规则。跨用户消息衔接：用户发来"继续"等消息后，注册新名称继续输出。

**多结果展开**（3+项时）：第一行汇总，后续每项独立一行。⛔每批≤8项，超限分多步骤标注输出（禁止单次输出中展开超过8项）。详见上方§16。
