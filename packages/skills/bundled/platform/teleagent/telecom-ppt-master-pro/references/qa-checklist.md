# QA Checklist (7 项逐页检查)

对每个渲染后的 `preview/page-N.png`，逐项检查这 7 条。任何一项失败，按 `troubleshooting.md` 修复并重新渲染。**在所有页通过之前不得声明完成。**

所有页通过后，再运行 `deck-qa-checklist.md` 的 Deck 级检查。

## 检查 1 · 内容在安全区域内

### 通用主题
- 所有文字、卡片、图片在 y=1.85 到 y=7.1 之间
- 没有内容被页脚遮挡（页脚在 y=7.1-7.5）
- 最底部元素 + 0.1 缓冲 ≤ 7.1

### 电信主题（telecom-red）
- 所有正文、卡片、图片在 y=0.55 到 y=7.05 之间
- 顶部 0~0.52" 为深红通栏保留区，禁止放置内容元素
- 底部 7.08~7.50" 为红色横幅保留区，禁止放置内容元素
- 最底部元素 + 0.1 缓冲 ≤ 7.05

## 检查 2 · 无裁剪或溢出文字

- 所有文字标签完全可见，无截断
- 右对齐标签有 ≥ 0.4" 右边距
- 多行文字不溢出卡片边界

## 检查 3 · 导航栏反映当前章节

### 通用主题
- 当前章节高亮为 `accentLight` 色，加粗 + 下划线
- 非活跃章节为白色常规字重

### 电信主题
- 顶部深红通栏显示 Deck 标题
- 红金渐变线位于通栏底部

## 检查 4 · 页脚显示正确页码和章节

### 通用主题
- 左侧：`作者 · 来源 · 上下文`
- 右侧：`章节 · 页码 / 总页数`（封面/TOC/致谢为 "—"）

### 电信主题
- 底部红色横幅，白字
- 左侧：`作者 · 单位/主题`
- 右侧：`章节 · 页码 / 总页数`（封面/致谢为 "—"）

## 检查 5 · 主题色使用一致

### 通用规则
- 无意外十六进制码——所有颜色来自主题 `C` 对象
- 主色：导航栏、"我方"标题、KPI 强调
- 强调色：标题左边栏、公式框、深色背景高亮
- 对比色：仅"问题"/"之前"标题，不用于正面内容
- 正文：`text`（近黑），说明文字：`muted`（灰）

### 电信主题额外检查
- 主色为 `C.primary`（电信深红 #C00000），数字目标必须红色加粗
- 金色(`C.accent`)仅用于装饰线和渐变接续
- 黄色高亮(`C.highlight`)仅用于数据/重点底色
- 卡片填充必须为 `C.iceLight`（浅粉 #FFF0F0），描边 `C.border`（浅红 #E8B4B4）
- 蓝色不得大面积做主色

## 检查 6 · 图片清晰且尺寸合适

- 嵌入图片不模糊不拉伸
- 纵横比保持不变（`sizing: { type: "contain", w, h }`）
- 生成文字默认 ≥ 12pt（脚注/说明/表格/图表标签均适用）
- 电信主题正文最小 7pt，正文 12pt，标题 14-16pt

## 检查 7 · 视觉层级清晰

- 一页回答一个问题
- 计划好的证明对象是主要焦点
- 留白充足——卡片间 0.2-0.3"，章节间 0.12-0.15"
- 阴影仅用于白底卡片，不用于彩色条
- 编号圆圈 0.42-0.45"

### 电信主题额外检查
- 量化指标必须红色加粗突出
- 三栏布局结构均衡
- 每条文字 ≤15字
- 红色竖条标记条目层级

## 按模板专项检查

### 封面 (T1)
- 标题水平垂直居中于中上部
- 作者块在标题下方有舒适留白
- 顶部/底部装饰条存在
- 电信主题：顶部深红通栏 + 底部深红横幅

### 目录 (T2)
- 编号列对齐
- 章节标题列对齐
- 行间距均匀

### 章节分隔 (T3)
- 大色块填充大部分安全区
- 编号大（≥ 80pt）且视觉主导
- 标题在编号下方，主色背景白字

### 图表 (T9)
- 坐标轴标签可读（≥ 12pt）
- 图例在底部，主题色
- Takeaway bar 单行加粗
- 电信主题：关键发现用深红底白字

### KPI (T13)
- 大数字视觉主导（≥ 48pt）
- 卡片等宽，内边距一致
- 电信主题：数字红色，卡片浅粉填充

### 表格 (T10)
- 表头深红底白字（电信主题）
- 交替行浅粉/白底
- 数据列对齐

### 总结 (T15)
- 三个 takeaway 盒使用三种不同强调色
- 闭合线栏底部全宽
- 电信主题：第三栏（目标成果）用红色反白

### 致谢 (T16)
- "Thank You" 居中、大字（≥ 50pt）
- Q&A 或联系信息在下方 muted 色

## 检查 8 · 模板锚定一致性（v6.0 新增）

仅在使用模板锚定（Layer 2）时检查。

### 全锚定模式
- 每页内容严格落在 Layout Map 对应占位符坐标内
- 文字字体与占位符字体规范一致（或 Overrides 有明确覆盖）
- 无占位符外的自由元素（除 Notes 中声明的外）

### 半锚定模式
- 关键区域（标题、数据区）坐标与 Layout Map 一致
- 装饰元素不遮挡锚定内容
- 自由元素的安全边界与模板保留区无冲突

### 灵感锚定模式
- 配色方案与模板主色调一致
- 字体家族与模板一致
- 间距/留白风格与模板协调

### 通用检查
- Layout Map 中引用的所有 layout 都有对应的 Template Contract 定义
- Anchors 中引用的占位符索引在 Layout Map 中都存在
- 无坐标冲突（两个元素不重叠在同一区域）

## 检查 9 · 表格精准落位（v6.0 新增）

仅当页面包含 Table Contract 时检查。

- 表格位置与 Table Contract 中 Position 坐标一致
- 列宽总和等于 Table Contract 中的 w 值
- 条件格式规则与 Table Contract 中 ConditionFormat 一致
- 自动点评文字存在且内容准确（与数据匹配）
- 表头样式符合主题规范（电信：深红底白字加粗）
- 交替行色正确应用
- 表格内容无溢出单元格
- 数字格式符合 ColSpec 规范（千分位、百分比等）

## 检查 10 · 微调指令精准执行（v6.0 新增）

仅当用户提出微调指令后执行。

- 微调操作与 `refinement-mapping.md` 映射表一致
- 目标元素准确识别（无遗漏、无误伤）
- 微调后的视觉效果与用户预期一致
- 微调未破坏原有布局完整性
- 微调已记录到 REFINEMENT_LOG.md
- 同类微调达到 3 次已标记为"待升级"

## 完成条件

1. 每页通过全部 7 项通用检查
2. 每页通过对应主题的专项检查
3. 每页通过模板专项检查
4. 至少每页渲染并目视检查一张 PNG
5. Deck 通过 `deck-qa-checklist.md`
6. 使用模板锚定时通过检查 8
7. 含 Table Contract 时通过检查 9
8. 执行微调后通过检查 10
9. 用户后续审查未提问题
