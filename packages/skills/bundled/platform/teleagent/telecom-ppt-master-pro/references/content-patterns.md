## 模式1：架构总视图（单页）

**输入类型**: Excel表格 / 架构图PNG / Markdown蓝图

**组织逻辑**: 8层自上而下，从问题到落地
```
1. 总标题
2. 三大牵引问题（是什么/要什么/怎么落）
3. 两大升级方向（标准升级 + 能力升级）
4. 四子模块展开（商机+配餐 | 个人+营业部）
5. 闭环管理机制（日/周/月三级管控）
6. 标杆打造路径（右侧：四步流程）
7. 底座基石（531底座 + 支撑说明）
8. 核心逻辑（标准→能力→标杆循环）
```

**PPT结构**: 单页，纵向分层，层级间虚线箭头串联

## 模式2：三栏精要（单页）

**输入类型**: Excel表格 / Markdown要点

**组织逻辑**: 三大并列板块
```
┌──────────┬──────────┬──────────┐
│ 标准升级  │ 能力升级  │ 管控+目标 │
├──────────┼──────────┼──────────┤
│ 商机扩围  │ 个人3提升 │ 闭环管理  │
│ 配餐优化  │ 营业部3提升│ 量化指标  │
│ 落地动作  │ 瓶颈定位  │ 531→2.0  │
└──────────┴──────────┴──────────┘
       底部标语（一行）
```

**PPT结构**: 单页，三栏卡片 + 底部标语

## 模式3：宣贯蓝图（多页）

**输入类型**: Markdown内容蓝图

**组织逻辑**: 封面 + 总视图 + 逐页展开
```
P0  封面（标题+副标题+日期）
P1  总视图架构图
P2  从1.0到2.0 — 为什么升级
P3-N 逐模块展开（每模块1-2页）
PN   结语+行动号召
```

**PPT结构**: 多页，每页遵循统一配色和排版

## 模式4：制度解读型（8-21页）

**输入类型**: 制度文件/管理办法/1号文件

**典型页面流程**:
```
P01  封面（制度名称+发文单位+日期）
P02  总体目标/总则
P03  组织领导与职责分工（三道防线）
P04  各部门职责（1/N）
P05  各部门职责（2/N）
P06  业务管理流程：事前-事中-事后（★闭环逻辑）
P07  风险三单机制
P08  责任体系与奖惩
P09  结语/链接
```

**页面构成**: 正文页(67%) + 指标数据页(11%) + 封面/结尾

**关键特征**:
- "三道防线"结构是通用模式
- "事前-事中-事后"闭环逻辑是电信管理核心框架
- 职责分拆常跨多页（1/N格式）

## 模式5：工作报告型（30-60页）

**输入类型**: 年度/季度工作总结

**典型页面流程**:
```
P01      封面（标题+口号+单位+日期）
P02      序言/致辞
P03      目录（4-6大板块）
P04-06   板块一：回顾总结（精神学习/政策解读）
P07-22   板块二：数据呈现（图表+趋势+区县排名）
P23-40   板块三：重点举措/成效展示
P41-55   板块四：展望与目标
P56-59   结语+致谢
```

**页面构成**: 正文页(31%) + 总结/展望页(22%) + 指标数据页(17%) + 表格数据页(15%) + 其他(15%)

**关键特征**:
- 59页的长PPT，是电信正式报告的典型规模
- 图表密集（Chart出现38次以上）
- 区县排名矩阵是最大特色（天长/琅琊/定远/南谯/来安/全椒/凤阳/明光+政企）
- 数据呈现方式：排名(33%) + 数值指标(92%) + 表格(58%) + 趋势描述(92%)

## 模式6：方案宣贯型（20-30页）

**输入类型**: 方案文档/优化方案

**典型页面流程**:
```
P01      封面
P02      目录（2-4个一级板块）
P03-06   板块一：变化点/背景（对比新旧规则）
P07-14   板块二：核心内容展开（逐项解读+表格对比）
P15-20   板块三：落地指引/积分规则
P21-22   总结/展望
P23-27   附件/补充材料
```

**页面构成**: 正文页(41%) + 表格数据页(48%) + 总结/展望页(4%) + 其他(7%)

**关键特征**:
- "变化点" 页是核心（新旧对比，突出差异）
- 表格占比极高（48%），需要表格呈现规范
- 目录页常出现多次（每个大板块前插入分目录）

## 模式7：演示指导型（15-20页）

**输入类型**: 产品演示/系统操作指导

**典型页面流程**:
```
P01      封面
P02-04   背景与目标
P05-06   流程总览
P07-12   按角色演示（系统管理员 1/4...4/4）
P13      操作演示模型
P14-15   注意事项
P16      总结+反馈链接
P17      附件链接
```

**页面构成**: 正文页(76%) + 表格数据页(6%) + 总结页(6%) + 其他(12%)

**关键特征**:
- **按角色分拆** 是核心组织模式（管理员/整改人员/复核人员...）
- 分页标注（1/4格式）确保不遗漏
- 底部常附链接（省公司反馈、流程文档等）

## 模式8：策略分析型（7-18页）

**输入类型**: 策略方案/打法/分析

**典型页面流程**:
```
P01      封面/标题页
P02      目录
P03-05   策略框架/方法论
P06-08   数据支撑/指标
P09-12   具体打法/案例
P13-16   资源配置/执行路径
P17-18   总结+行动号召
```

**页面构成**: 正文页(50%) + 总结/展望页(28%) + 其他(22%)

**关键特征**:
- 英文标题/副标题使用较多（如 Sales Strategy & Presentation Guide）
- 总结/展望页占比高（28%），强调行动号召
- EXECUTION 是高频关键词

## 模式9：运营推进型（8-10页）

**输入类型**: 运营机制/推进方案

**典型页面流程**:
```
P01      封面
P02      为什么需要？（问题→需求）
P03      是什么？（定义/标准）
P04      怎么做？（流程/闭环）
P05-06   工具使用（一线人员 vs 管理人员）
P07-08   链接/演示/结语
```

**页面构成**: 正文页(75%) + 总结/展望页(13%) + 封面页(12%)

**关键特征**:
- **Why→What→How** 三段式是核心逻辑
- 按受众分拆（一线人员 vs 管理人员）
- 极简页数，每页信息密度高

| 维度 | knowcard产品培训 | 内部汇报PPT |
|---|---|---|
| **信息类型** | 信息传达型（高文字密度、多表格、精确布局） | 汇报演示型（AutoShape装饰、色块分割、视觉图形） |
| **配色体系** | 科技蓝`#0070C0`+科技青`#64FFDA`+浅紫灰`#CCD6F6`配合电信红 | 红+黑+白+黄为主，蓝色仅辅助 |
| **封面设计** | 86%极简（2-3个Shape，全幅背景图+标题+单位） | 70%居中全幅（3-5个Shape，标题+副标题+日期+装饰线） |
| **导航模式** | 链接返回导航页（TeleDB风格的目录可点击回跳） | 传统线性翻页，无超链接 |
| **截图使用** | 1×1占位大表格作截图容器（全宽表格嵌入系统界面图） | 截图较少，多用CHART图表 |
| **语言风格** | 中英双语标题(如"破局之道：智能体引领变革 / The Solution: Agents Leading...") | 纯中文标题 |
| **字体** | Noto Sans SC（产品培训常用） | 微软雅黑（内部PPT绝对主导） |

## 模式11：风险管控案例型（8-15页）

**输入类型**: 风险案例/违规分析/管控流程

**典型页面流程**:
```
P01  封面
P02  风险概览（主要风险3-5条）
P03  问题-举措双栏页（左:主要风险9.6cm + 右:端到端流程21.6cm）
P04  风险案例四格块页（2案例并排，各14.5cm宽）
P05  风险案例四格块页（续）
P06  闭环逻辑（事前→事中→事后，椭圆节点+连接线）
P07  整改方案与复核标准
P08  管控流程图（燕尾箭头连接）
```

**关键特征**:
- **风险案例四格块**: 每案例 = 案例简述 + 风险现象 + 整改方案 + 复核标准，2案例并排
- **"问题-举措"双栏**: 左栏"主要风险"（9.6cm深红圆角容器）+ 右栏"端到端流程"（21.6cm），燕尾箭头连接
- 配色使用`#B80106`(流程节点)、`#1F2937`(案例标题)、`#4B5563`(案例描述)
- "事前-事中-事后"闭环逻辑是风险PPT的核心框架

## 模式13：商机诊断分析型（单页）

**输入类型**: 营业部商机数据 / 通报表格

**组织逻辑**: 三栏非对称——数据诊断 + 行动路径 + 管控目标
```
┌──────────────┬────────────────┬──────────────┐
│ 一、商机结构   │ 二、三步行动法   │ 三、管控指标   │
│   诊断        │                │              │
├──────────────┼────────────────┼──────────────┤
│ □ 总商机数    │ Step1 分类分级  │ 商机转化率     │
│   N户        │ • 异网→48h优先 │ ≥30%         │
│ □ 已转化      │ • 续约→提前1月  │              │
│   N户|N%     │ • 普通→周计划   │ 异网占比       │
│ □ 沉淀未转    │ Step2 精准跟进  │ ≥35%         │
│   N户|N%     │ • 配餐到人日清   │              │
│ □ 异网商机    │ • 必查消费+痛点  │ 闭环完整率     │
│   N户|N%     │ • 3天未转→介入  │ ≥98%         │
│              │ Step3 闭环复盘  │              │
│ 沉淀细分(N)  │ • 转化→订单号    │ 日录入量       │
│ 异网未到期 N │ • 沉淀→标记归因  │ ≥3单/天      │
│ 加装未转 N   │ • 周复盘→优化   │              │
│ 价格犹豫 N   │                │ 48h跟进率     │
│ 竞品对比 N   │                │ 100%         │
│ 触达未果 N   │                │              │
├──────────────┴────────────────┴──────────────┤
│ 核心理念：商机录入不是终点，而是经营起点         │
└──────────────────────────────────────────────┘
```

**关键特征**:
- 左栏4个数据卡片（红/橙/绿三色区分重要性）+ 5类细分分析（每类含数量+占比+原因+建议）
- 中栏3步卡片（每步含3条具体动作，红标题+灰正文）
- 右栏5行指标表（指标名+计算规则+达标值，达标值红色大号字）
- 细分分析**数据必须闭合**：所有细分项总和 = 沉淀总数
- 底部一行核心理念总结

**适用场景**: 商机诊断 / 短板分析 / 营业部数据拆解 / 对标改进

│01 做了什么│02 怎么干 │  03 落到哪（红底白字）  │

│• 举措1   │• 能力1   │• 成果1 量化对比        │
│  描述    │  描述    │                      │
│• 举措2   │• 能力2   │• 成果2 量化对比        │
│  描述    │  描述    │                      │

## 内容提炼规则（MANDATORY）

1. **输入分析**: 先通读全部源材料，标记所有量化数据
2. **层级划分**: 识别天然的三级结构（大类→子类→条目）
3. **精简提炼**: 每条目 ≤15字，去冗余修饰词
4. **数字标记**: 所有 `≥`、`%`、`≥N场/人/单` 类型目标标记为重点
5. **三栏判断**: 内容自然分3类时优先三栏布局，4类时可用四子模块
6. **底层逻辑**: 始终在底部保留一句核心逻辑/转变标语
7. **类型识别**: 根据输入内容自动判断属于哪种内容模式，按对应流程组织
8. **knowcard识别**: 文档标题含"竞品/资费/销售/技术/交付/运维/培训/QA"关键词时，匹配knowcard编号9-16对应流程
9. **竞品展示选择**: 仅1个竞品→双栏对比；2个竞品→四列表格；流程对比→三栏并列
10. **风险页面选择**: 有案例→四格块布局；有问题+举措→双栏布局；有闭环→三步骤流程图
11. **数据闭合检查**: 细分分析页的所有子项数值之和必须等于标题中的总数；总结收尾页的目标值要与前文承诺一致
12. **总结页设计**: 三栏卡片（做了什么/怎么干/落到哪）+ 底部红色横幅（逻辑链→最终目标），第三栏红底反白
13. **章节定位判断**: 生成前先确认页面所在PPT章节。第二章"存在问题"→问题导向（VS对比暴露差距）；第三章"升级方案"→能力导向（递进箭头展示链路）
14. **安全边界检查**（v4.3 新增）: 所有元素必须在有效内容区（y=0.55"∼7.08"）内；多条目使用高度均分 `itemH = (可用高度)/条目数`，禁止固定间距叠加；生成后运行越界检查脚本确认无 `[OVERFLOW]`

15. **座谈会模式识别**: 当用户提到"座谈会""半年会""经营复盘""高管发言"等关键词时，匹配模式16-19，使用T17-T24模板+executive-blue主题+executive-symposium预设
16. **分公司画像页设计**: 分公司数量≤4用单页2×2网格(T20)；5-8用双页2×2网格；>8用分组三组分栏(T21)
17. **结论先行规则**: 座谈会/复盘模式的每个数据页，顶部必须有蓝色加粗结论条(2-3行)，底部必须有蓝/红判断条(1行)
18. **剪刀差量化要求**: 分公司分析页必须量化好差公司之间的PP差距，不得只说"有差距"而不给具体数值

当输入为 Excel 数据时，根据数据特征自动选择以下模式。这些模式与现有15种内容模式并行，在数据驱动场景下优先推荐。

| 模式 | 数据特征 | 页面结构 | 模板 | Table Contract |
|------|---------|---------|------|---------------|
| ED1 排名速览 | 有1个排序主维度（如地市排名） | KPI卡Top3 + 完整排名表 + 点评 | T13 + T10 | 必填，含条件格式 |
| ED2 时间对比 | 有时间维度（月/季/年） | 对比图表 + 关键变化点评 | T9 | 可选 |
| ED3 构成分析 | 有占比/构成数据 | 饼图 + 结构点评 | T9(pie) + T13 | 可选 |
| ED4 多维仪表盘 | 3-6个独立指标 | 网格KPI + 迷你图表 | T14 | 每格1个mini Table Contract |
| ED5 交叉透视 | 2个维度交叉（如地市×业务） | 双栏：左卡片区+右数据表 | T12 + T10 | 必填 |

### Excel 驱动模式选择流程

```
用户上传Excel
  → Step1: 识别数据维度（行/列/时间/分类）
  → Step2: 判断主维度特征
    → 有排名维度？ → ED1
    → 有时间维度？ → ED2 或 ED6（看是否有预警指标）
    → 有占比维度？ → ED3
    → 3-6个独立指标？ → ED4
    → 两个维度交叉？ → ED5
  → Step3: 推荐模式给用户确认
  → Step4: 填写 Table Contract + Slide Contract
```

### Excel 驱动模式与现有模式的关系

Excel 驱动模式是**页面级**的布局选择，可以嵌入现有15种内容模式中：

- 模式5 工作报告型 → 内部大量页面使用 ED1/ED2/ED4
- 模式8 策略分析型 → 数据支撑页面使用 ED1/ED5
- 模式11 风险管控案例型 → 风控数据页面使用 ED1/ED6

## 图形布局推荐 (v7.1)

> 以下规则在识别内容大纲后，自动推荐最合适的图形布局模板(T25-T34)。
> 引擎代码：`assets/graphic-layouts.js`，匹配规则：`references/graphic-layout-guide.md`

### 识别→推荐矩阵

| 内容逻辑特征 | 推荐布局 | 对应模板 | 示例场景 |
|---|---|---|---|
| 含日期/阶段/先…再…最后 | 时间轴 | T25 | 历程回顾、季度推进 |
| 含流程/步骤/输入→输出 | 流程箭头 | T26 | 业务流程、加工链 |
| 含总分/分层/层次/架构 | 金字塔或总分结构 | T27/T29 | 需求层次、组织架构 |
| 含循环/闭环/PDCA/轮转 | 循环图 | T28 | 持续优化、闭环管理 |
| 含漏斗/转化/逐层递减 | 漏斗图 | T30 | 销售转化、流失分析 |
| 含基础+支柱+目标/保障 | 殿堂框架 | T31 | 保障体系、支撑框架 |
| 含自上而下/下沉/推进 | 垂直步骤 | T32 | 下沉执行、推进部署 |
| 含升级/进阶/逐步提升 | 阶梯进化 | T33 | 能力升级、进阶路径 |
| 含价值链/上下游/端到端 | 价值链 | T34 | 产业链、端到端流程 |

### 使用规则

1. **识别大纲后先推荐图形布局**：在 Step 1 需求解析阶段，对提取的内容结构执行 `recommendLayout()` 分析
2. **图形布局优先于卡片布局**：当内容有明确逻辑结构（时间/流程/层级/循环等）时，优先使用T25-T34，而非T7三卡片
3. **卡片布局仍用于**：无明确逻辑结构的并列要点、对比分析、纯数据展示
4. **可在同一页混合使用**：如左侧用T29总分结构展示架构，右侧用T26流程展示执行路径
5. **与diagram-drawing协作**：复杂决策流程/泳道图/鱼骨图等超出原生形状能力的，调用diagram-drawing生成PNG嵌入
