# 任务路由

本文件是任务模式选择的唯一权威来源。先根据用户希望得到的结果选择一条主路线，再决定需要哪些关卡和工具。

## 决策树

```text
输入是否包含需要保留的现有 PPTX？
├─ 是：用户主要要求修改现有页或保留现有原生行为
│  └─ edit-native-deck
├─ 是：用户主要要求把该文件变成可复用模板/起始工程
│  └─ create-template-workspace
└─ 否：从材料、数据或大纲创建演示
   └─ create-new-deck
```

如果一个请求同时命中多条路线，选择最能保护现有资产的一条作为主路线，并把其他路线作为子阶段。例如：“基于旧 PPT 更新本月数据并新增 5 页”默认走 `edit-native-deck`，新增页面作为其子阶段。

## 路线合同

| 路线 | 主要输入 | 必须输出 | 默认关卡 | 默认编辑策略 |
|---|---|---|---|---|
| `create-new-deck` | Word、Excel、文本、图片、数据、模板 | PPTX、计划、设计锁、QA 报告 | 来源、需求、计划、设计、生成、QA、交付 | 自动选择生成引擎 |
| `edit-native-deck` | 现有 PPTX + 修改要求 | 新 PPTX、change set、QA 报告 | 来源、变更、保真、QA、交付 | PowerPoint 自动化/最小 OOXML/受控 python-pptx |
| `create-template-workspace` | 模板 PPTX | Layout Map、设计锁、预览、3 页样例 | 模板分析、能力、样例、QA | 模板分析器 + 起始构建器 |

## 何时需要需求锁定

- `create-new-deck`：默认需要；如果用户输入已覆盖高影响字段，直接形成锁定单，不重复提问。
- `edit-native-deck`：只有修改会改变业务结论、数据口径、页面结构、模板或交付物时才启用相关字段。
- `create-template-workspace`：只锁定模板用途、输出范围、目标引擎和保真要求，不询问业务内容。

## 原生编辑能力边界

按以下顺序选择：

1. PowerPoint 自动化：适合需要最大程度保留动画、备注、SmartArt、嵌入对象和复杂关系的 Windows 环境。
2. 最小 OOXML 修改：适合少量确定的 XML 字段替换，必须先备份并验证包关系。
3. `python-pptx`：适合新增/修改常见文本框、形状、表格和图片；不承诺保留所有 PowerPoint 特性。
4. 重建页面：只有用户接受重建和保真差异时使用。

## 停止条件

出现以下任一项时，只暂停受影响分支并向用户说明：

- A 级需求未知或来源冲突会改变内容结论。
- 无法在不破坏用户要求保留的原生对象前提下完成编辑。
- 指定模板、字体、品牌资产或渲染器不可用且没有等价回退。
- 正式交付要求视觉 QA，但环境中没有可用渲染器。
