# 需求锁定关卡

在制作任何页面、Slide Contract 或生成代码之前使用本关卡。目标是一次问清所有会改变内容、结构、数据解释、模板或交付物的未知项，同时避免重复询问已知信息。

## 1. 执行原则

1. 先检查用户消息、附件、文件名、现有模板和环境。
2. 从证据中填写已知项，记录来源；不要先发一张固定问卷。
3. 将未知项按风险分类。
4. 一次性分组询问所有高影响未知项，推荐值放在问题中。
5. 用户回复“未说明项按推荐默认值”时，只默认 B/C 级字段；没有安全默认的 A 级字段仍需确认。
6. 用户确认需求锁定单后，才进入内容结构和页面规划。
7. 制作过程中出现新的高影响未知项时暂停相关分支并询问；不影响其他已确认工作的部分可继续。

## 2. 状态定义

| 状态 | 含义 | 是否阻塞 |
|---|---|---|
| `known` | 用户或权威材料明确给出 | 否 |
| `inferred` | 由上下文可靠推断，已说明依据 | 视影响等级 |
| `unknown` | 缺失且无法安全推断 | 高影响时阻塞 |
| `defaulted` | 用户授权采用推荐默认值 | 否 |
| `confirmed` | 用户已确认 | 否 |
| `conflict` | 不同来源互相矛盾 | 是 |

## 3. 风险等级

### A 级：必须确认

- 汇报目标或希望受众采取的行动
- 核心受众、会议场景和汇报时长
- 权威内容/数据来源及冲突时的优先级
- 数据周期、单位、统计范围、分母和是否允许推算
- 必须保留、必须删除、禁止出现的内容
- 模板来源与锚定模式
- 页数或可用时长
- 保密等级、是否允许联网补充或引用外部资料
- 会显著改变工作量或交付结果的输出要求

### B 级：可推荐后确认

- 主题、预设和创意方向
- 目录层级和章节顺序
- 图表类型、颜色语义和数据标签密度
- 是否需要演讲备注、PDF、预览图、源代码
- 文件名、作者、单位、日期和页脚字段

### C 级：可自动默认

- 16:9 画布
- 中文微软雅黑、英文和数字 Arial
- 标准 QA 模式
- 常规电信场景使用 `telecom-red`
- 未指定时使用简洁正式中文
- 输出文件名按主题自动生成

A 级字段必须是 `known` 或 `confirmed`；不得用 `defaulted` 绕过。B 级未知项可成组给出推荐值；C 级直接在锁定单中披露默认值。

## 4. 字段清单

### 4.1 业务目标

| 字段 | 示例 | 推荐默认 |
|---|---|---|
| `purpose` | 通报、决策、宣贯、培训、争取资源 | 无，必须确认 |
| `desired_action` | 会后落实三项动作 | 无，必须确认 |
| `success_criteria` | 领导确认方案、完成宣贯 | 与目的对应 |
| `tone` | 高管决策、正式通报、培训讲解 | 正式简洁 |

### 4.2 受众与场景

| 字段 | 示例 | 推荐默认 |
|---|---|---|
| `audience` | 省公司领导、区县负责人、客户经理 | 无，必须确认 |
| `meeting` | 月度经营分析会 | 从材料推断后确认 |
| `duration_minutes` | 10、20、30 分钟 | 无，必须确认 |
| `presentation_mode` | 现场讲解、材料传阅、两者兼顾 | 现场讲解 |

### 4.3 内容边界

| 字段 | 示例 | 推荐默认 |
|---|---|---|
| `source_of_truth` | Excel > Word > 旧 PPT | 用户提供的最新文件 |
| `must_include` | KPI、问题、措施、责任人 | 从用户材料提取 |
| `must_exclude` | 敏感名单、未发布政策 | 无，必须确认敏感项 |
| `rewrite_permission` | 可压缩、不可改结论 | 可压缩，不改变事实 |
| `external_research` | 禁止/允许并需引用 | 禁止 |

### 4.4 数据口径

| 字段 | 示例 | 推荐默认 |
|---|---|---|
| `period` | 2026年1–7月 | 无，必须确认 |
| `scope` | 全市、区县、渠道 | 无，必须确认 |
| `unit` | 户、万元、%、PP | 沿用源文件 |
| `denominator` | 有效客户数 | 无，必须确认 |
| `calculation_permission` | 可计算同比/环比 | 仅做可复核计算 |
| `missing_value_policy` | 留空、不展示、标 N/A | 标 N/A，不估算 |

当不同文件的数据不一致时，标为 `conflict`，展示差异及文件来源，不得自行选一个值。

### 4.5 篇幅与结构

| 字段 | 示例 | 推荐默认 |
|---|---|---|
| `page_count` | 12页 | 按时长估算后确认 |
| `mandatory_sections` | 总览、问题、举措、保障 | 目的驱动 |
| `detail_level` | 高管摘要/业务细节 | 受众驱动 |
| `appendix` | 明细表放附录 | 数据密集时使用 |

时长与页数推荐：快速通报 0.7–1.0 页/分钟；高管讨论 0.5–0.8 页/分钟；培训 1.0–1.5 页/分钟。只作为建议，不替代用户确认。

### 4.6 模板与品牌

| 字段 | 选项 | 推荐默认 |
|---|---|---|
| `template_mode` | 用户模板、内置5G模板、默认电信红 | 电信场景推荐内置5G模板 |
| `anchoring` | 全锚定、半锚定、灵感锚定 | 内置5G为全锚定 |
| `theme` | telecom-red、executive-blue 等 | 按场景自动推荐 |
| `logo` | 用户提供、模板内置、不使用 | 沿用模板 |
| `footer` | 单位/作者/日期/页码 | 按模板规范 |

用户已上传模板或明确指定模板时，不再询问是否使用内置5G模板。先分析上传模板，再确认锚定模式。

### 4.7 输出与技术要求

| 字段 | 选项 | 推荐默认 |
|---|---|---|
| `aspect_ratio` | 16:9、4:3、自定义 | 16:9 |
| `editable_charts` | 是/否 | 是 |
| `speaker_notes` | 是/否 | 否 |
| `animation` | 是/否 | 否 |
| `deliverables` | PPTX、PDF、PNG、源代码 | PPTX |
| `qa_mode` | 快速、标准、严格 | 标准 |
| `output_name` | 指定文件名 | 主题+日期 |

不要直接询问用户选择 pptxgenjs、python-pptx 或 SVG。先询问结果要求，再自动路由引擎。

### 4.8 合规与记忆

| 字段 | 选项 | 推荐默认 |
|---|---|---|
| `confidentiality` | 公开、内部、敏感 | 内部 |
| `internet_allowed` | 是/否 | 否 |
| `long_term_memory` | 记住/仅本项目 | 仅本项目 |
| `sensitive_fields` | 人名、号码、客户数据 | 不外发、不联网 |

## 5. 一次性提问格式

优先控制在 5–8 个分组问题内，每个问题可包含同一主题下的多个短字段。

```text
我已经从材料中确认：{known_summary}。

开始制作前还需确认以下高影响事项：
1. 目标与受众：这份材料用于什么会议、给谁看，希望会后达成什么结果？
2. 时长与篇幅：汇报时长或目标页数是多少？
3. 内容边界：哪些内容必须保留、必须删除，是否允许压缩改写？
4. 数据口径：统计周期、单位、范围和权威数据源是什么？
5. 模板品牌：使用上传模板、内置5G模板，还是默认电信红？
6. 输出要求：是否需要可编辑图表、备注、PDF、动画或严格逐页QA？
7. 合规：材料保密等级，是否允许联网补充？

未说明项可以回复“按推荐默认值”。
```

## 6. 需求锁定单

使用简明表格展示，不要暴露技术实现细节：

| 类别 | 已锁定内容 | 状态 | 来源/默认依据 |
|---|---|---|---|
| 目标 | ... | confirmed | 用户回复 |
| 受众 | ... | confirmed | 用户回复 |
| 数据 | ... | known | 文件名/工作表 |
| 模板 | ... | defaulted | 场景推荐 |
| 输出 | ... | confirmed | 用户回复 |

结尾必须显示：

```text
blocking_unknowns: 0
conflicts: 0
ready_for_planning: true
```

任一 A 级字段仍为 `unknown` 或 `conflict` 时，`ready_for_planning` 必须为 `false`。

## 7. 机器可读结构

可将需求锁定单保存为项目工作区中的 `deck-requirements.json`：

```json
{
  "version": 1,
  "has_data": false,
  "fields": {
    "purpose": {"value": "经营复盘", "status": "confirmed", "risk": "A", "source": "user"},
    "audience": {"value": "市公司领导", "status": "confirmed", "risk": "A", "source": "user"},
    "aspect_ratio": {"value": "16:9", "status": "defaulted", "risk": "C", "source": "skill-default"}
  },
  "blocking_unknowns": [],
  "conflicts": [],
  "ready_for_planning": true
}
```

使用 `scripts/validate_requirements.py` 校验该文件。校验器会独立扫描所有 `risk: A` 字段，不信任手工填写的 `blocking_unknowns`；校验只判断关卡状态，不替代用户确认。
