# 内容、标题与版式映射

## 1. Customer-controlled narrative

Do not lock the deck to one content sequence. First determine what the customer needs the audience to understand, compare, approve, remember, or do. Then choose the most suitable narrative model.

Common options include:

- question → analysis → answer;
- current status → key findings → requested decision;
- chronology or development history;
- product or capability overview by module;
- comparison of options, regions, products, or periods;
- process, architecture, or operating mechanism;
- case collection organised by customer, scenario, or business line;
- achievement evidence grouped by theme;
- training content → practice → application;
- person or team story organised by experience and representative deeds;
- problem → action → result, only when that logic genuinely fits.

The reference deck supplies layouts and visual language. It does not prescribe the number, names, or order of sections.

## 2. Direct title rules

Put the recognisable subject first. Put the strongest outcome or page claim second.

Preferred patterns:

- `[项目名]：把[旧状态]改善为[新状态]`
- `[系统名]：[规模]对象在[时间]内可见`
- `[平台名]：将[事项A、事项B、事项C]集中管理`
- `[应用名]：[知识/服务规模]实现[服务结果]`
- `[安全主题]：把风险控制贯穿[阶段范围]`
- `[团队主题]：[人数]能够独立[能力范围]`
- `[培训主题]：[场次]覆盖[人数/对象]`

Good style examples:

- `PON割接自动化：100个PON口准备从5天压缩到2小时`
- `网络在线分析系统：1万多个通信点位状态2分钟可见`
- `安全研发与AI测试：把风险控制贯穿项目全过程`
- `AI赋能培训与团队共创：30余场培训覆盖3000余人次`

Do not copy these facts into a new deck unless its sources verify them.

Avoid:

- vague slogans such as “向难而行”“创新引领未来”;
- titles that require reading the body to identify the project;
- repeated “从……到……” structures across many slides;
- excessive abstractions, stacked nouns, and advertising language;
- internal production notes or prompt wording.

## 3. Page logic options

Choose the page logic from the customer’s question. Examples:

| Customer need | Suitable page logic |
|---|---|
| Explain a project improvement | problem → action → evidence → meaning |
| Present a product | positioning → modules → scenarios → differentiators |
| Request a decision | decision point → options → comparison → recommendation |
| Review current work | objectives → completed items → risks → next actions |
| Show achievements | theme → evidence → scale → organizational value |
| Explain a process | trigger → stages → control points → output |
| Explain architecture | layer or module → relationship → data flow → boundary |
| Tell a person or team story | experience → representative deeds → standards → influence |
| Deliver training material | concept → method → demonstration → practice |

Do not add a background block, solution block, or result block merely because the reference slide contains one. Rewrite or repurpose inherited slots to match the selected logic while preserving the visual hierarchy.

Always explain the meaning of important evidence, but place it where the chosen narrative needs it.

## 4. Reference layout library

Use the retained deck as a layout library. Map content to the closest pattern.

| Reference slide | Use when | Core composition |
|---|---|---|
| 1 | Cover | Minimal centered title, subtitle, presenter, bottom wave |
| 2 | Timeline, profile, organization, or overview with one main image | Structured facts on left; one main image and compact information bands on right |
| 3 | Process, comparison, staged method, or metric-led explanation | Explanatory blocks on left; steps, metrics, and synthesis on right |
| 4 | Dashboard, system, product, or multi-evidence page | Main screenshot plus two evidence slots on left; three compact explanatory blocks on right |
| 5 | Large-screen product, service, result, or customer-experience page | Three stacked text blocks on left; large screenshot and one prominent takeaway on right |
| 6 | Application scene, case photo, person, or product demonstration | Large photo on left; three stacked explanatory blocks on right |
| 7 | Three-part framework, security, quality, governance, or assurance | Evidence strip above; three-stage or three-theme blocks below; summary at left |
| 8 | Team, organization, ecosystem, customer, or capability page | Large group/context photo; two text blocks and three metrics |
| 9 | Multi-topic, training, portfolio, activity, or media showcase | Top metrics; three or four image modules; bottom synthesis |
| 10 | Closing | Minimal synthesis and company-value statement |

Reuse a source slide more than once when appropriate, but vary titles, evidence, and emphasis. Do not use one layout for the whole deck.

## 5. Example structures, not mandatory templates

Use these only as inspiration when they match the customer request. Do not insert a section merely because it appears below.

### Project or innovation report

1. Cover
2. Background/current situation
3. Project case 1
4. Project case 2
5. Project case 3
6. Safety/quality/repeatability
7. Team or organizational impact
8. Next actions or closing

### Advanced-role or craftsman presentation

1. Cover
2. Personal experience and current role
3. Practical result
4. Innovation result
5. Difficult problem and safety standard
6. Team influence
7. Training or knowledge transfer
8. Closing

Use the four-character tags only as subtle thematic anchors when the customer needs them. Always attach them to evidence.

### Training or communication report

1. Cover
2. Audience and goal
3. Key content or method
4. Delivery scenes
5. Practice outputs
6. Coverage and feedback
7. Replication plan
8. Closing

## 6. Speaker-note rules

- Choose the voice for the customer and presentation type. Use natural first-person Chinese for a personal report; use an appropriate organizational, product, decision, or teaching voice for other decks.
- Follow the source logic. Use chronology only when chronology helps the current message.
- Explain the context, evidence, implication, transition, or presenter experience needed for that page; do not force all five into every note.
- Use concrete verbs and project language.
- Keep facts identical to the visible slide and source materials.
- Avoid model-like openings such as “今天我想交流的不是……而是……”.
- Avoid exaggerated heroic language and artificial emotional elevation.
- Avoid repeatedly stressing “一线、基层、边疆” when the audience shares similar working conditions.
- Let the visible slide carry structure and data; let the note carry the transitions and context the audience needs.

## 7. Evidence hierarchy

Prefer evidence in this order:

1. verified source data;
2. real system screenshot or report;
3. real project, training, team, or duty photo;
4. authentic certificate or recognition;
5. editable placeholder for later replacement;
6. abstract illustration only when clearly non-evidentiary.

Never fabricate evidence to make the page look complete.
