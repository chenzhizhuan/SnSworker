# 七条核心原则完整说明

> 本文件是提示词进化器技能的详细参考，由 SKILL.md 按需加载。
> 目录：原则1~7，每条含核心思想、正反对比、实操要点，末尾含跨原则协同关系。

---

## 原则1：给足背景（上下文原则）

**核心思想**：把 AI 当成一个聪明但对你一无所知的新同事。提问前先想——一个值得信任的顾问需要知道哪些信息才能给你靠谱答案？把这些都告诉 AI。

**关键要点**：
- 背景信息越具体、越个性化，AI 的回答越能跳出常识框架
- 可以上传文件、图片、录音等作为背景素材
- AI 的上下文容量可达约 75 万词，不必吝惜背景信息

> **子维度：目标明确性**。给足背景不仅包括"你是谁"，还包括"你要什么"——目标必须明确可衡量，这是原则1的内在组成部分。

**对比**：

| 维度 | 反例（背景不足） | 正例（背景充分） |
|------|-----------------|-----------------|
| 健身 | 帮我做个健身计划 | 我 38 岁，新手，只有十磅哑铃，每天练 15 分钟，家里有蹦床，养了猫，很难坚持 |
| 投资 | 帮我查下基金行情 | 我是互联网行业从业者，业余关注基金投资，风险偏好保守，本金约X元，帮我查本周基金市场涨跌情况 |
| 写作 | 帮我写篇文章 | 我在通信行业工作 5 年，需要写一份技术认证备考方案，目标读者是和我一样的在职备考人员 |
| 编程 | 帮我写个脚本 | 我用 Python 3.10，Windows 环境，需要从 CSV 读取销售数据，按月汇总后生成柱状图，输出到本地文件夹 |

**实操清单**（至少回答 3 个）：
1. 你是谁？（身份、角色、经验水平）
2. 为什么要做这件事？（目的、动机）
3. 结果给谁用？（读者画像）
4. 有什么前提条件或限制？（资源、时间、预算）

## 原则2：中立提问（避免讨好倾向）

**核心思想**：AI 天然倾向于说你想听的话（Sycophancy），必须主动规避。提问时不流露期望的答案方向，或者提供一套客观评分标准让 AI 按依据回答。

**对比表**：

| 错误问法（有暗示） | 正确问法（中立） |
|-------------------|-----------------|
| 远程办公是不是比坐班更好？ | 远程办公和坐班相比，生产力水平孰高孰低？请分别列出支持数据 |
| 碳税是不是对小微企业不好？ | 碳税在多大程度上影响了小微企业？请客观呈现正反证据 |
| 你同意 AI 会创造大量就业吗？ | 目前的研究怎么说 AI 对就业的影响？请引用至少2个来源 |
| 这篇论文写得很棒吧？ | 请按以下标准评估这篇论文：准确性30%、完整性30%、逻辑性20%、创新性20% |
| 这只基金是不是很好，值得买吧？ | 这只基金近3个月表现如何？请列出涨跌幅、最大回撤和同类排名 |

**完整提示词级对比**：

反例：
```
帮我分析一下远程办公的好处，我觉得远程办公效率更高，你觉得呢？
```

正例：
```
请客观比较远程办公与坐班办公的工作效率，要求：
1. 分别列出支持远程办公和坐班效率更高的研究数据
2. 指出两种模式各自最大的优势（各1条）和劣势（各1条）
3. 不需要给出"哪种更好"的结论，只呈现事实
```

**实操要点**：
- 把"是不是/好不好"替换为"在多大程度上/数据怎么说/按标准评估"
- 提供客观评分标准（如：准确性 30%、完整性 30%、逻辑性 20%、创新性 20%）
- 在提示词中加入「请客观呈现正反两方面的证据」

## 原则3：渐进迭代（不要一步到位）

**核心思想**：不要让 AI 直接写成品，而是分阶段打磨。每个阶段有明确的输入、输出和反馈环节。

> **与原则4的区别**：原则3是纵向的时间递进（先地基再盖楼），原则4是横向的空间拆分（分几队人各盖一面墙）。先拆块（原则4），再对每块迭代（原则3），两者协同效果最佳。

**写作场景黄金流程**：
```
给 AI 背景素材
  → 让它列 3 个大纲方案
  → 你对方案提反馈（喜欢什么、不喜欢什么、补充新想法）
  → AI 修改大纲 → 你再反馈 → 反复几轮
  → 满意后展开为要点 → 再反馈
  → 最后才让 AI 写正文
```

**头脑风暴场景**：
```
让 AI 给 3~5 个方案
  → 你反馈好恶和补充信息
  → AI 出新一轮方案
  → 迭代到满意
```

**实操要点**：
- 在提示词中加入「请先给出大纲/方案，我确认后再逐步展开」
- 每轮只聚焦一个层面（大纲→要点→正文），不要跳级
- 反馈时明确说"保留X、删掉Y、补充Z"

## 原则4：分块处理（化整为零）

**核心思想**：把大任务拆成小任务逐个处理。每个子任务聚焦一个明确目标，降低一次性生成大篇幅内容的质量风险。

**编辑文章**：不要一口气让 AI 改全篇，而是一段一段改，每段让 AI 给几种不同风格供选择。

**评分反馈**：给 AI 设定明确的评分标准（如角色塑造 25 分、情节 25 分），每项标准只有"是/否"两种结果，杜绝模糊打分。

**对比**：

| 反例（整块处理） | 正例（分块处理） |
|-----------------|-----------------|
| 帮我分析整个通信行业 | 先分析5G基站建设现状 → 再分析运营商资本开支趋势 → 最后看设备商竞争格局 |
| 帮我重写这篇文章 | 逐段修改：第一段先给出3种风格供选择，确认后再改第二段 |
| 帮我评估这个方案 | 按以下标准逐项评估：可行性(是/否)、成本(是/否)、风险(是/否) |

**实操要点**：
- 提示词中明确拆分步骤：「请按以下顺序逐步处理：1. … 2. … 3. …」
- 每步输出后等待用户确认再继续
- 评分标准用二元判定（是/否）替代模糊打分
- 分块步数建议不超过 7 步，超过时考虑合并相近步骤

## 原则5：选对工具（检索与工具策略）

**核心思想**：根据问题类型选择合适的信息来源和工具，避免用错工具导致信息过时或不足。

**策略对照表**：

| 问题类型 | 该用什么 | 示例 |
|---------|---------|------|
| 常识、基本事实 | 直接用预训练知识，秒回 | 手机掉汤里咋办、什么是5G |
| 时事新闻、特定地点、冷门信息 | 开启网络搜索（online_search） | 今日股市行情、某地天气预报 |
| 需要综合多方观点的复杂问题 | 用深度研究技能（deep-research） | 某行业发展趋势分析、竞品调研 |
| 需要计算或数据分析 | 写代码并运行（powershell/Python脚本） | 投资回报率计算、数据可视化 |
| 需要生成专业文档 | 用文档生成技能（docx） | 写技术方案、合同审查 |
| 需要制作演示文稿 | 用 PPT 技能（pptx） | 做汇报PPT、培训课件 |
| 需要处理表格数据 | 用 Excel 技能（xlsx） | 销售数据分析、财务报表 |
| 需要制作信息图 | 用信息图技能（infographic） | 行业概览图、流程图 |
| 需要生成网页交互 | 用 Web 构件技能（web-artifacts-builder） | 交互式仪表盘、计算器 |

**实操要点**：
- 在提示词中明确指定信息来源：「请使用网络搜索获取最新数据」或「请基于你的知识回答」
- 需要多源验证时指定：「请从至少 3 个来源交叉验证此信息」
- 如果不确定，可以先让 AI 判断信息类型再选工具
- 涉及多步骤任务时，不同步骤可指定不同工具（如：第一步用搜索，第二步用代码分析）
- 代码执行类任务需注意环境限制：Windows 环境、PowerShell 可用、Python 按需安装依赖

## 原则6：触发思考（让 AI 深度推理）

**核心思想**：处理复杂任务时，核心机制是"提供充分上下文 + 要求结构化输出"，而非仅靠几句触发词。丰富的背景信息（呼应原则1）和明确的输出结构要求，才是真正触发深度推理的关键。触发词只是辅助。

**有效触发方式（按重要度排序）**：

| 优先级 | 触发方式 | 说明 |
|--------|---------|------|
| 1 | 提供充分上下文 | 背景越丰富，AI 思考越深入（呼应原则1） |
| 2 | 要求结构化输出 | "请分3个维度分析，每个维度列出论点和数据" |
| 3 | 要求展示推理过程 | "请列出你的推理步骤和依据" |
| 4 | 辅助触发词 | "请认真思考"、"请逐步推理"、"请仔细分析后再回答" |

**实操要点**：
- 复杂任务优先选用最强模型
- 提供充分上下文（呼应原则1），让 AI 有足够信息进行深度推理
- 不要把一个复杂任务拆得过碎（与原则4平衡），适当保持任务的整体性以触发深度思考
- 在提示词结尾加一句「请认真思考后再回答」作为辅助
- **注意**：不同模型对触发词的响应不同，"ultra think"等非通用指令不保证生效，结构化输出要求更可靠

## 原则7：上下文卫生（换话题开新对话）

**核心思想**：聊新话题时开新对话，清空无关上下文，避免之前对话干扰新问题的回答质量。只保留对当前问题真正有用的背景信息。

**实操要点**：
- 换话题时明确声明：「本对话仅讨论XXX，与此前内容无关」
- 开新对话时，只带入当前任务必需的背景（如角色设定），丢弃上一轮的具体内容
- 长对话中如果 AI 开始跑偏，检查是否因为早期上下文干扰
- 执行不同任务时主动建议用户「建议开一个新对话处理这个话题」

## 跨原则协同关系

七条原则并非独立工作，它们之间存在依赖和增强关系，组合使用效果更佳：

```
原则1（给足背景）──→ 原则6（触发思考）
   ↑                    ↑
   │  充分上下文是深度推理的前提  │
   └──────────────────────┘

原则3（渐进迭代）+ 原则4（分块处理）
   │  先横向拆分，再纵向递进
   │  例：把大报告拆成3章（原则4），每章先大纲后正文（原则3）
   └────────────────────────

原则2（中立提问）+ 原则7（上下文卫生）
   │  旧上下文容易引入偏见
   │  换话题时既清空上下文（原则7），也检查问题措辞是否中立（原则2）
   └────────────────────────

原则1（给足背景）──→ 原则5（选对工具）
   │  明确任务类型才能选对工具
   └────────────────────────
```

**典型协同组合**：

| 场景 | 协同原则 | 搭配方式 |
|------|---------|---------|
| 写长篇报告 | 1+3+4 | 给足背景→拆分章节→逐章迭代 |
| 深度调研 | 1+2+5+6 | 给背景→中立提问→选深度研究→要求推理过程 |
| 创意内容 | 1+3+7 | 给风格参考→先出3个方案→保持话题聚焦 |
| 数据分析 | 1+4+5+6 | 给数据背景→按维度拆分→用代码工具→要求逐步推理 |
