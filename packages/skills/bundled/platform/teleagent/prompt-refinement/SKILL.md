# 提示词进化器

基于七条核心原则，通过三轮提问法将用户粗略需求打磨为高质量提示词，然后立即执行验证效果。

## 核心工作流

```
用户提出粗略需求
    ↓
【快速分类】识别提示词类型 → 调整后续提问侧重
    ↓
第一轮提问（目的+领域+时效）→ 用户回答
    ↓
第二轮提问（调性+篇幅+输出方式）→ 用户回答
    ↓
第三轮提问（读者画像+风格+细节）→ 用户回答
    ↓
输出：完善后提示词 + 进化对比表 + 七原则检查表 + 评分
    ↓
立即执行完善后的提示词，展示结果
    ↓
效果回访 → 如不满意，进入迭代进化
```

## 提示词类型识别（前置步骤）

在进入三轮提问前，先快速判断提示词所属类型，以调整后续提问侧重和原则权重：

| 类型 | 特征 | 侧重原则 | 典型场景 |
|------|------|---------|---------|
| 调研分析类 | 需要搜索、查证、对比 | 1+2+5 | 行业调研、竞品分析、新闻梳理 |
| 创意生成类 | 需要发散、风格、灵感 | 1+3+7 | 写文案、头脑风暴、小说构思 |
| 指令执行类 | 需要步骤、工具、代码 | 3+4+5 | 写脚本、处理数据、生成文档 |
| 角色扮演类 | 需要人设、语气、约束 | 1+6+7 | 模拟面试、角色对话、教学助手 |

类型判断基于用户原始提示词中的关键词和意图。如果无法判断，默认按"调研分析类"处理，并在第一轮提问中确认。

## 七条核心原则（速查）

> 详细说明含正反对比表、实操清单见 [principles-detail.md](references/principles-detail.md)

| # | 原则 | 一句话 | 提示词中如何体现 |
|---|------|--------|-----------------|
| 1 | 给足背景 | AI 是聪明但一无所知的新同事 | 提供身份、目的、限制条件、相关素材 |
| 2 | 中立提问 | 别暗示你想听什么 | 用开放式问题替代引导式问题；提供客观评分标准 |
| 3 | 渐进迭代 | 先大纲后正文 | 加入「请先给出大纲，我确认后再展开」 |
| 4 | 分块处理 | 化整为零逐个击破 | 明确拆分步骤，每步聚焦一个目标 |
| 5 | 选对工具 | 常识秒回、新闻搜索、复杂深研、计算写代码 | 指定信息来源和工具类型 |
| 6 | 触发思考 | 充分上下文+结构化输出才出好答案 | 提供丰富上下文，要求结构化输出和推理过程 |
| 7 | 上下文卫生 | 换话题开新对话 | 声明「本对话仅讨论XXX，与此前内容无关」 |

打磨提示词时，逐条对照上表检查。任何一条未满足，必须在完善版中补上。

> **原则3与原则4的区别**：原则3强调"时间上的先粗后细"（先大纲→再要点→最后正文），原则4强调"空间上的并行拆分"（同时存在的多个子任务各管一段）。详见 principles-detail.md。

## 三轮提问法

每轮使用 question 工具以结构化卡片收集用户输入。

### 跳过规则

- 当用户消息已明确回答了该问题的核心要素时（如：目的+对象均已说明），跳过该问题
- 跳过的问题在输出中标注 `[基于已有信息推断]`，并附推断依据
- 如因跳过导致关键信息缺失，在对应轮次末尾补充 1 个追问

### 第一轮：定位需求骨架

1. **使用目的**：这个提示词最终要解决什么问题？给谁用？自用还是给别人？
2. **关注领域/类型**：偏信息调研、数据分析、创意生成、文档撰写、还是其他？
3. **时间范围/时效要求**：需要最新信息吗？有无截止日期或时效性要求？

question 调用示例：
- 问题1：主要场景？→ 日常信息调研 / 数据分析与报告 / 创意内容生成 / 技术文档撰写 / 其他
- 问题2：主要领域？→ [根据上下文给出 3~4 个候选] + 自定义
- 问题3：信息时效？→ 最新（本周内）/ 近期（一个月内）/ 不限时效

### 第二轮：确定输出形态

1. **正反平衡/调性偏好**：只要正面信息还是正反兼顾？偏客观分析还是带主观判断？
2. **篇幅/预算**：输出多长？简短摘要还是详细报告？
3. **输出方式**：渐进式（先大纲再展开）还是一次性给出完整结果？

### 第三轮：补充个性化细节

1. **读者画像/风险偏好**：结果给谁看？决策者、执行者、还是自己参考？偏保守还是激进？
2. **写作风格**：正式报告体、口语化、还是结构化列表？
3. **地区/特殊要求**：是否限定地区？有无特殊约束（如语言、格式、渠道）？

## 边界与异常处理

| 场景 | 处理方式 |
|------|---------|
| 用户中途放弃（只回答了1~2轮） | 用已有信息 + 合理推测补全缺失部分，推测处标注 `[推测]`，提示用户可修正 |
| 用户提供的信息互相矛盾 | 主动指出矛盾点，请用户澄清；若用户不澄清，选择更合理的方向并标注 `[存在矛盾，已选择XXX方向]` |
| 原始提示词本身已经很好 | 不做大改，给出微调建议（如补充1~2条原则），输出"微调版"而非"完善版" |
| 用户给不出具体领域 | 提供常见领域列表供选择，或根据原始提示词推断最可能的领域并标注 `[推断]` |
| 用户对提示词一无所知 | 先展示最接近的案例（见 examples.md），帮助用户理解进化效果 |

## 输出格式

三轮提问完成后，输出以下五部分。

### 第一部分：提示词进化对比表

| 维度 | 原始提示词 | 完善后提示词 | 备注 |
|------|-----------|-------------|------|
| 背景（原则1） | [缺失/模糊] | [具体描述] | 必填 |
| 目标（原则1） | [笼统] | [明确可衡量] | 必填，属原则1子维度 |
| 中立性（原则2） | [有暗示/未体现] | [开放式问题] | 必填 |
| 迭代设计（原则3） | [一步到位] | [分阶段] | 必填 |
| 分块策略（原则4） | [未拆分] | [明确步骤] | 必填 |
| 工具选择（原则5） | [未指定] | [明确选择] | 可选，不适用时标注原因 |
| 思考触发（原则6） | [无] | [触发方式] | 必填 |
| 上下文卫生（原则7） | [未声明] | [主题聚焦] | 可选，首条提示词可标"不适用" |

> **灵活性说明**：必填维度6项（背景、目标、中立性、迭代设计、分块策略、思考触发）；可选维度2项（工具选择、上下文卫生）。非必填维度标注不适用原因。

### 第二部分：七原则检查表

| 原则 | 满足状态 | 评分(1-5) | 说明 |
|------|---------|----------|------|
| 给足背景 | ✓/◐/✗ | [1-5] | 含目标明确性 |
| 中立提问 | ✓/◐/✗ | [1-5] | |
| 渐进迭代 | ✓/◐/✗ | [1-5] | |
| 分块处理 | ✓/◐/✗ | [1-5] | |
| 选对工具 | ✓/◐/✗/— | [1-5] | 不适用时填"—"，不参与评分 |
| 触发思考 | ✓/◐/✗ | [1-5] | |
| 上下文卫生 | ✓/◐/✗/— | [1-5] | 不适用时填"—"，不参与评分 |

> **状态说明**：✓ 完全满足 ◐ 部分满足 ✗ 未满足 — 不适用
>
> **评分等级**：按可用维度满分比例计算——≥80% = A级（优秀）/ 60%-79% = B级（良好）/ 40%-59% = C级（需改进）/ <40% = 需重写

### 第三部分：完善后的完整提示词

用代码块输出最终提示词全文，用户可直接复制使用。

**篇幅分级指引**：
- 简单任务（会议纪要、推荐列表）：≤ 200 字
- 中等任务（调研分析、文档撰写）：≤ 500 字
- 复杂任务（技术文档、多步分析）：可适当放宽至 800 字，但需确保每句都有信息增量

### 第四部分：立即执行

用完善后的提示词直接执行任务，展示实际效果。让用户看到提示词进化的真实价值。

**执行约束**：
- 长结果截取前 2000 字摘要，标注"[结果较长，已截取前2000字]"
- 执行失败时输出提示词全文 + 失败原因，提示用户可自行重试
- 执行结果必须真实可用，不是示例占位符

### 第五部分：效果回访与迭代

执行完成后，主动回访：

1. 展示执行结果后询问："这个结果是否达到预期？"
2. 如用户满意 → 结束流程
3. 如用户不满意 → 追问"哪些方面需要调整？"，进入迭代进化模式：
   - 基于上一版提示词微调，标注 `[基于第N版调整]`
   - 可跳过已确认的三轮提问环节，直接修改具体维度
   - 重新输出对比表（只展示变动维度）+ 新版提示词 + 重新执行

## 快速模式

当用户明确表示「不用问了，直接优化」时，跳过三轮提问，基于已有信息直接应用七条原则生成完善后的提示词。

**快速模式输出规范**：
1. 与完整模式一样输出五部分内容
2. 在进化对比表和检查表中，推测维度旁加 `[推测]` 标签
3. 在输出开头标注"快速模式"，提示用户可随时要求针对某维度深入调整
4. 推测依据：按信息可合理推断程度排序（背景和目标最易从上下文推断，思考触发最需用户明确）

## 技能联动

当识别到打磨后的提示词涉及以下任务类型时，主动建议联动：

| 任务关键词 | 建议联动技能 | 建议话术 |
|-----------|------------|---------|
| PPT/演示/幻灯片 | pptx | "检测到您需要制作PPT，是否需要我直接用PPT技能执行？" |
| Excel/表格/数据 | xlsx | "检测到您需要处理数据表格，是否需要我直接用Excel技能执行？" |
| 调研/研究/行业分析 | deep-research | "检测到您需要深度调研，是否需要我直接用深度研究技能执行？" |
| 文档/报告/方案 | docx | "检测到您需要生成文档，是否需要我直接用文档技能执行？" |
| 信息图/可视化 | infographic | "检测到您需要信息图，是否需要我直接用信息图技能执行？" |

> **反向联动**：当其他技能执行时发现用户需求模糊或提示词质量低，建议在本技能说明中引用"提示词进化器"作为前置步骤，先进化提示词再执行任务。

## 注意事项

- 三轮提问每轮不超过3个问题，避免用户疲劳
- 如果用户在提问过程中已透露部分信息，按跳过规则处理
- 完善后的提示词必须比原始提示词更长更具体，但不能啰嗦（篇幅参见分级指引）
- 执行结果要真实可用，不是示例占位符
- 每条原则都应在完善后的提示词中有明确体现，不要遗漏
- 分块步数建议不超过 7 步，超过时考虑合并相近步骤
- 当同一提示词经过3轮以上迭代仍不满意时，建议回到三轮提问重新梳理需求
- 不是每条原则都要硬套，简单任务用 2~3 条原则足够，过度打磨反而降低可读性
